# 动态交易策略（通用层）

本文件是**通用层策略**：状态机索引 + 跨战法通用细则（选股六池 / 题材阶段状态机 / 止损 / 时间止损 / T+1 / 输出规范 / 复盘流程 / 教训附录），供 agent 执行盘面分析与复盘。各阶段战法本体在 `memory/strategies/` 分册，不重复进本文件。

> - **流程控制 + 必调接口 + 关键字段含义 + 通用字段消费纪律** → 见总纲 `AGENTS.md`
> - **认知与纪律（红线 + 术语字典）** → 见心法 `memory/trading-mindset.md`
> - **市场阶段判定（今天是什么天）** → 见裁决层 `memory/strategies/00-regime-machine.md`（执行权威为 journal 状态机代码）
> - **各阶段操作方案（这种天怎么打）** → 见战法分册 `memory/strategies/10~40-*.md`

## 状态机索引（每轮第 0 步）

**当前阶段怎么看**：盘中每轮第 0 步调 `cli.py journal.read_regime_state --trade_date <当日>`（本地读、先于总纲 §3.1 其余 4 项）——返回 `current_state`（阶段）、`state_label`（中文）、`next_day_channel_open`（尾盘通道资格）、`defensive_reason`（陈旧 / 长假防御，非空 → 当日按防守处理并记录）。**agent 只读代码输出，禁止手工推演转移表**；`code != 200` 同样按防守处理并记录。

**四层开仓裁决矩阵（一笔新开仓必须同时通过，各层互不覆盖、取最严）**：

| 层 | 裁决问题 | 输入 | 不通过时 |
|----|----------|------|----------|
| ① 市场层（状态机） | 今天的阶段允许开仓吗？用哪套买点细则？ | `regime-state.json`（前日盘后代码写入） | 防守 / 预备：禁新开仓；冰点：三通道（资格 `next_day_channel_open`——通道 A 冰中博弈 / 通道 A2 早盘拉起博弈 / 通道 B 尾盘认证）；主升 / 震荡：对应分册细则 |
| ② 当日层（LLM 两指标） | 当日盘面是否恶化到禁开仓？ | 当帧 `sentiment_label` + `sentiment_capital_alignment`（§0.1） | `偏保守/保守` + `退潮` 同时满足 → 当日禁开新仓（即使主升态） |
| ③ 账户层（position_limit） | 最多开多少？ | `final_analysis.position_limit` 直接采用 | 超限不开；已有持仓不因上限降低被强卖 |
| ④ 个体层（心法红线） | 这个标的能买吗？ | 监管名单 / 四类股 / 撤退方向 0% / 单只 30% / 同方向 50% / 套利四要素 / 不打板不接力 | 否决标的或收敛仓位 |

> **层①适用于一切新增买入动作**（含分册 T+2 加仓、§2.4 分笔建仓的补足笔——补足 / 加仓视同新开仓过层①）；止损止盈、减仓、清仓等卖出动作不受状态机限制（风控不设时间窗）。矛盾记录进 `regime_track` 供进化分析。

**分册路由表（阶段 → 战法文件）**：

| 晨起阶段 | 战法 | 允许行为 |
|----------|------|----------|
| 防守（默认兜底） | `40-retreat-defense.md` | 禁一切新开仓（含尾盘通道）；持仓风控照常（不设时间窗）；记录观察照常 |
| 冰点（2 ≤ 簇深 ≤ 4） | `10-ice-point.md` | 试错三通道（当日合计出手一次）：通道 A 冰中博弈（当帧短线仍 ≤25）+ 通道 A2 早盘拉起博弈（9:36~11:00，当帧短线 >25 拉起确认）+ 通道 B 尾盘认证（条件见分册） |
| 冰点（簇深 <2 或 ≥5） | `40-retreat-defense.md` | 同防守（深度 ≥5 长熊防御，通道关闭） |
| 主升预备 | `40-retreat-defense.md` | 同防守（只观察确认，不出手） |
| 主升 | `20-main-uptrend.md` | 主升战法全量启用（受层②③④约束） |
| 高位震荡 | `30-high-oscillation.md` | 震荡战法启用（收敛、禁追、只做贯穿主线回踩） |

**与题材层状态机（§2.3）的正交关系**：题材状态机判定"这个题材处于什么阶段"（买点类型选择依据，本文件保留）；市场状态机判定"今天是什么天"（能否出手的资格，裁决层）。两台状态机串联：市场层给资格 → 题材层给买点。例：主升态 + 题材"再分歧" → 有资格但该题材不参与；防守态 + 题材"启动 Day 1" → 题材再热也不开仓（只能记录观察）。

## 核心原则（一行版）

**选股用趋势三池 + 主力净流入榜 + 成交额榜 + 小时热度榜六池合并（筛选标准一致、形态这道门槛照常卡）；开仓资格过四层矩阵（市场层状态机 × 当日层 LLM 两指标 × 账户层 position_limit × 个体层心法红线，见「状态机索引」）；仓位、情绪取盘面分析原值不调档；个体纪律用心法卡，操作细节按本文件。**

## 零、跨战法通用字段消费

> 下列是跨战法通用的字段消费细则。通用字段含义见总纲 §3.2，通用字段消费纪律（不自创标签 / 不自拾指标 / 名单非门槛 / 信号≠动作 / 持仓必采分时）见总纲 §5.1，字段缺位判定见总纲 §5.2，退化规则见总纲 §5.3 / §5.4，不以偏概全见总纲 §5.5。

### 0.1 仓位采用与开仓触发

> **角色定位**：本节开仓触发部分是四层开仓裁决矩阵（「状态机索引」）的**当日层（②）**，与市场层状态机 AND 叠加——状态机给资格后，本节两指标再判当日盘面是否恶化到禁开仓；仓位部分是矩阵的**账户层（③）**。

**仓位（直接采用，不自行调档）**

- **唯一字段**：`final_analysis.position_limit`
- **直接采用**作为本轮**新增可动用**仓位上限，**不主动降、不主动加**；`position_limit` 只约束"是否还能开新仓"，**已有持仓不因 `position_limit` 降低而被强卖**（持仓去留归 §三 止盈止损 + §0.2 撤退方向判定，**不**因仓位低而强卖进攻方向持仓）
- 个体持仓上限（心法 §五：单只 ≤ 30%、同方向 ≤ 50%）**同时**生效
- 整轮流程：先读 `final_analysis.market_overview`（必读）→ 再读 `position_limit` → 用 `position_limit / 100` 作为总仓位上限
- **禁止**：不复述 `position_reasoning` 区间 / 上下沿 / 微调；不基于 `sentiment_label` / `confidence` 调档；不基于"主锚 / 权重 / 核心信号"调档

**开仓触发（两指标联合判定）**

**唯一判定**：是否开新仓由 `sentiment_label` + `sentiment_capital_alignment` 两者联合判定。

> 与心法 §三 仓位哲学的关系：心法四象限（短线差大盘差→禁止）与本节 `alignment=退潮→禁` 是**同一判定的两种表述** —— `sentiment_capital_alignment` 是盘面分析把短线温度与资金进攻方向综合后的落地信号（共振 / 虚热 / 强撑 / 退潮：情绪好差 × 有无进攻方向四象限）。心法哲学是底层依据，本节是可执行判定，不另立第四条件。

**禁开仓条件（两者同时满足）**：

| 字段 | 条件 |
|------|------|
| `sentiment_analysis.sentiment_label` | ∈ {`偏保守`, `保守`} |
| `final_analysis.sentiment_capital_alignment` | == `退潮` |

- 两者同时满足 → **停止开新仓**（禁开仓只作用于"新仓"，**不等于**清掉已有持仓；已有持仓去留归 §三 止盈止损（含 §3.0 环境分层减仓）+ §0.2 撤退方向判定）
- 任一不满足 → 仍可按 `position_limit` 执行
- **alignment 的卖出侧含义**：`alignment == 退潮` 未叠加保守情绪时不禁开仓，但已构成持仓侧 §3.0 环境分层减仓的触发条件（开仓与减仓两个维度各自生效，不互相豁免）

> 短线交易每天都会有新题材和持续发酵的方向，情绪温度回答"当前是否适合开新仓、能上多少仓"。具体做哪个题材、位置高低是否接盘，参照盘面分析的题材分析（`hot_rotation_analysis`）字段 + 选股买点纪律各自把关，**不**用一个全局风险等级去一概而论地否定开仓。

**判定原则**：
- 只用 `sentiment_label` + `sentiment_capital_alignment` 两指标，不自创"主升 / 回暖 / 混沌 / 退潮"等标签
- `sentiment_label` 单独**不**禁开仓 —— 只有同时叠加 `alignment=退潮` 才禁
- 大盘温度（`temperature_score` / `temperature_label`）**不**作开仓过滤器

### 0.2 活跃方向判定（方向有参考价值，个股名单只是样本，不当门槛）

**活跃方向** = 近期反复活跃、持续发酵的热点题材。来源（取并集，任一即可）：
- `final_analysis.attack_directions[].direction`（盘面分析二次筛选后的进攻方向）
- 顶层 `data["attack_directions"]`（次要参考）
- `hot_rotation_analysis.attack_sectors[].sector`（题材分析识别的进攻方向）

> **方向 vs 个股名单的辨证（核心认知）**：
> - **方向**（`direction` 字段，如"光通信 / 光纤"）是盘面分析综合资金流、轮动、情绪后给出的**方向性参考**，有决策价值 —— 它帮助柚子 AI 聚焦近期资金主攻的板块。
> - **个股名单**（`direction` 下的 `stocks[].code`）只是盘面分析论证该方向时引用的**样本个股**，受限于喂给它的数据源（成交额榜 / 资金流榜等），**有偏且不完整**。趋势股池里完全可能有形态更优、买点更好、但名单没列出来的标的。
> - **结论**：方向用于聚焦视野与同方向持仓判定；**个股名单不直接进选股池、不作为个股取舍的裁判、不作为仓位分档依据**（§一 选股筛选）。买不买某只股，由趋势形态 + 买点 + 纪律**自主分析**决定。

活跃方向的作用范围（**只做这两件事，不做其它**）：
1. 聚焦选股视野 —— 优先在该方向覆盖的板块里找买点
2. 同方向持仓判定 —— 用于心法 §五（同方向 ≤ 50% 红线）

**不**作选股硬门槛，**不**要求"三角验证同时满足才算活跃方向明确"，**其下的 `stocks[].code` 名单更不是门槛**。

**撤退方向识别**（必须保留，红线）：

盘面分析的 `retreat_directions[].stocks[].code` 只是论证撤退方向时引用的**样本个股**，受限于数据源，**有偏且不完整**。名单漏列不代表脱离撤退方向，名单不卡 —— **判定依据是板块归属 + 主营细分**。

- 调 `cli.py market.get_stock_info <code>` 取 `hot_categories`（热点分类列表）+ `up_reason`（涨停原因 / 主营业务描述）
- 持仓股 `code` ∈ 任意 `final_analysis.retreat_directions[].code`，**或**持仓股 `hot_categories` 中**任一分类**与某 `retreat_directions[].direction` 字面匹配或同板块 → 已撤退方向（红线 0%，立即清仓）
- **同板块内细分方向（应用端 vs 制造端）**：当 `retreat_directions[].direction` 与 `attack_directions[].direction` 共享**同一板块名词**（典型：`CPO/光模块` 既可能出现在撤退方向、也可能以"光通信应用端"形式出现在进攻方向），必须用 `up_reason` 关键字二次细分：
  - **撤退方向细分关键字**（"制造端"特征）：`光模块` / `CPO` / `PCB` / `液冷` / `服务器机柜` / `封装` / `芯片制造` / `800G/1.6T 高速光器件` 等
  - **进攻方向细分关键字**（"应用端"特征）：`光纤` / `光缆` / `光棒` / `光器件应用` / `光通信运营` / `算力租赁` / `AI 应用` 等
  - `up_reason` 含撤退方向关键字 → 已撤退方向（红线 0%）；含进攻方向关键字 → **不**视为撤退方向（属活跃方向）
- 名单（`stocks[].code`）只作交叉验证参考，名单漏列不代表脱离撤退方向

**判定流程优先级**（不能省略任一步骤）：

1. **盘面直接列出的撤退个股**（`final_analysis.retreat_directions[].stocks[].code`）→ 直接判定为撤退方向，**优先剔除**。名单漏列不代表脱离撤退方向，但**名单列出的更应优先剔除**
2. **hot_categories 标签驱动**：仅当 `hot_categories` 包含盘面 `retreat_directions[].direction` 字面词汇（如 `大金融/证券/保险/银行` 或 `光通信/CPO/光模块`）时，才进入下一步细分。**不能因为某股 hot 包含多个标签就只看第一个**
3. **up_reason 二次细分**（仅当步骤 2 命中）：用主营描述判定撤退方向细分关键字 vs 进攻方向细分关键字，**主营细分占优**才判定为撤退
4. **未命中任何判定** → 不视为撤退方向（即使盘面 `attack_directions` 包含相似板块名词）

**常见错误**：
- ❌ 一只股 hot 为 `['CPO', '光通信', 'AI硬件']` → "含 CPO" 直接判撤退。**正解**：进入步骤 3，用 `up_reason` 细分主营是制造端（CPO/光模块）还是应用端（光纤/算力租赁）
- ❌ 一只股 hot 为 `['PCB', 'AI硬件', '业绩线']` → "PCB 在光通信撤退关键词里" 直接判撤退。**正解**：PCB 不在盘面 `retreat_directions[].direction` 字面词汇中（除非盘面明确将 PCB 列入撤退），不应自动判撤退

**同方向持仓判定**（心法 §五 仓位红线前提，仅用于 50% 红线，不用于个股取舍）：
- 持仓股 `code` ∈ 任意 `final_analysis.attack_directions[].stocks[].code`，**或**持仓股所属板块与某活跃 `direction` 同板块 → 视为同方向（上限 50%）。名单只是判定辅助，名单漏列不代表不同方向（板块归属为准）
- 持仓股 `code` ∈ 任意 `final_analysis.retreat_directions[].code` → 已撤退方向（红线 0%）

### 0.4 撤退、风险、操作（直接采用盘面结论）

| 盘面字段 | 含义 | 策略动作 |
|----------|------|----------|
| `final_analysis.retreat_directions[].code` | 撤退方向关联个股 | 同方向持仓纳入减仓（红线 0%） |
| `final_analysis.risk_warnings[]` | 风险提示 | 出现任一即纳入决策参考（不单独禁开仓） |
| `final_analysis.action_advice` | 操作建议 | **必读但需独立校验** —— LLM 对盘面的理解性提示，agent 应优先关注其指出的方向/风险；但具体买卖必须再经 §二 买点规则、§三 止损止盈、§0.2 撤退方向判定、§1.1 六池合并选股独立验证。出现"逢低吸纳 X""重仓 Y"等字样时，**不**等于 X/Y 已自动出现买点，禁止跳过技术规则直接执行。 |
| `final_analysis.vs_prev_analysis` | 与上次对比 | 持仓所属方向走弱 / 降级 / 逆转 → **当轮即启动 §3.0 环境分层减仓**（首笔逢高当轮执行，分批节奏见 §3.0）；每笔减仓的具体时机由当轮盘中分时判定，**禁止外推为"明日开盘第一时间 X"的跨日预承诺**（总纲 §5.1 第 4 条） |
| `sentiment_analysis.key_signals[看空+强]` | 加重风险信号 | 与 `risk_warnings` 一起纳入决策（总纲 §3.2 key_signals 分级） |
| `hot_rotation_analysis.retreat_sectors[].risk_level == "可能蔓延"` | 撤退风险分级 | **只回避该撤退方向**（不买其个股、持仓减仓）；**不封杀进攻方向开仓**，开仓资格仍归 §0.1（总纲 §5.5）（**仅当整段不为 None 时生效**） |
| `hot_rotation_analysis.retreat_sectors[]` | 资金撤退方向 | 同方向持仓纳入减仓候选；新仓回避该方向个股 |
| `final_analysis.observe_directions[]` | 未达门槛的观察方向（苗头） | **苗头待确认**：无当日资金量化证据，盘中不自动买卖（不计入撤退判定、不触发减仓、不进选股、不当撤退回避）；**复盘纳入当日方向事实记录（连续强势天数滚动累计）**，其后续是否升级由后续交易日盘中盘面重新判定 |
| `hot_rotation_analysis.emerging_sectors[]` | 新冒头方向（最多 2 个） | **轮动预期差主通道（§0.8.1）**：`signal` 当日资金动作 + `key_stocks` 风向标当日集体上攻双确认达标 → 按 Day 1 买点 5 参与方向内标的（分笔试错）；未达标只观察、不买卖。不当撤退回避 |

### 0.5 套利资金面验证

套利标的须满足**主力净流入 > 0 且换手率 ≥ 5%**（资金承接 + 活跃度双重确认，心法 §4.3 套利资金面合规红线）。数据取自三池候选集的 `main_amount` / `turn_z`，或 `cli.py market.get_stock_info <code>`。主力净流出标的**不**进套利评估。

**资金面取数口径（防悬空）**：
- 候选集 `main_amount` 是**格式化字符串**（如 `"2.3亿"` / `"--"`）：判"净流入 > 0"前必须解析数值；`"--"` / 空 / 解析失败 = **无数据**，不得当作任何方向的证据，转用 `get_stock_info` 的 `amount_main`（主力净额，元）
- `amount_main` 再缺位（None / 字段缺失）→ 用 `get_stock_minute_trendline` 的 `y2` 末值（当日主力净额，单位亿）兜底；**三级来源全部缺位 → 按"该字段为空，无法判定"处理，否决买入**（资金承接是硬条件，缺证据 ≠ 通过）

### 0.6 加速止盈分时形态判定（分时字段）

加速止盈是**形态信号**，只能从分时序列 + 主力净额识别，**禁止用持仓快照的涨跌幅 / 浮亏% 代替**（给不出形态，见总纲 §3.3 与 §5.1 第 5 条）。对每只**可卖持仓**（`available_volume > 0`；当日买入 T+1 不可卖的盘中跳过一切卖出导向分析，见总纲 §3.3）按需调 `cli.py market.get_stock_minute_trendline <code>`（分时：`labels` 时间序列 + `y1.data` 涨跌序列 + `y2.data` 主力资金序列，`y2` 末值为当日主力净额；**服务端已预计算 `fund_trend`（资金趋势）与 `fund_divergence`（资金背离），直接读取即可**），其中：

- `fund_trend`：主力资金分时趋势方向，三态——`steady_inflow`（持续流入）、`steady_outflow`（持续流出）、`flat`（平稳 / 方向不明 / 序列点不足）
- `fund_divergence`：服务端已判定是否出现"价格收涨但主力资金持续流出"的背离，直接取 `divergence` / `normal`

再按需调 `cli.py market.get_stock_info <code>`（板块归属 `hot_categories` / `up_reason`），按下表判四信号；**同时注意**：`y2` 主力资金序列呈"先入后出"形态（前段净流入上行、后段持续回落且末值显著低于日内峰值）**不限于加速止盈场景**——在买入候选侧出现时，即使 `fund_divergence == "normal"`，也提示早盘流入资金已开始兑现，日内回踩可能是派发而非健康承接，必须结合多日趋势位置与当日成交量综合判断，不可仅凭"主力净流入为正"就视为资金承接：

| 信号 | 判定 |
|------|------|
| 放量滞涨 | 冲高回落 / 不创新高 **且** 当日成交量（成交额）未较近期明显萎缩；因分时接口无分钟级成交量，"量能"以日级 `volume` / `amount` 相对近 5 日均量是否显著放大或维持为判据 |
| 长上影线 | 日内最高涨幅 − 收盘涨幅 **≥ 4%** |
| 走势与板块背离 | 所属 `attack_directions` 当日集体走强，个股却冲高回落 / 逆势走弱 |
| 资金背离 | 涨幅 > 0（`y1` 末值 > 0）**且** `fund_divergence == "divergence"`（服务端已判定：`fund_trend == "steady_outflow"` 且价格收涨、当前主力净额为负）**且** 主力净额量级显著（相对当日成交额占比明显，非尾盘轻微流出）→ 预警，**滞涨转跌**才确认卖出。若 `fund_divergence == "normal"`，**不**构成背离，**不**据此否决买入 / 触发止盈 |

任一信号成立即加速止盈。出现任一异常默认倾向卖出、需明确理由才留（心法 §4.5 六条心得"优先保住利润"）。

### 0.7 量价持续性判断（买入 / 持有共用）

> 具体术语含义（上涨缩量回踩、持续放量上攻、量价齐升、放量滞涨、放量冲高回落、放量下跌、缩量阴跌）见心法 `memory/trading-mindset.md`「七、术语字典」。本节只规定本账号的**决策用法**与**可执行判定口径**，不重复定义术语本身。

**核心原则**：量价健康是判断题材 / 个股是否仍有持续性的第一指标。买入前必须确认处于"可持续"状态，持有期间若出现"衰竭"信号则加速止盈。

### 健康信号（可持续）—— 决策含义

| 信号 | 决策含义 |
|------|----------|
| **上涨缩量回踩** | 洗盘干净，趋势未坏，可观察低吸 |
| **持续放量上攻** | 资金持续流入，主升健康，可持有或跟随 |
| **量价齐升** | 资金与价格共振，强势信号 |

### 衰竭信号（不可追 / 应止盈）—— 决策含义

| 信号 | 决策含义 |
|------|----------|
| **放量滞涨** | 主力出货，买入否决 / 持有止盈 |
| **放量冲高回落** | 上攻乏力，买入否决 / 持有止盈 |
| **放量下跌** | 抛压重，趋势可能反转，买入否决 / 持有止损 |
| **缩量阴跌** | 无人问津，不是低吸对象 |

### 使用纪律

- **买入侧**：必须满足至少一个健康信号（上涨缩量回踩 / 持续放量上攻 / 量价齐升），且未出现任一衰竭信号。禁止只看方向或涨幅，忽略量价
- **持有侧**：健康信号维持则持有；出现任一衰竭信号，按 §三 加速止盈处理
- **低吸买点**：尤其依赖"上涨缩量回踩"——若回踩时未缩量，或反而放量下跌，说明不是洗盘而是真出货，直接否决
- **判定数据来源**：
  - 日级成交量对比：调 `get_stock_daily_history`（含 `volume` / `ma5_volume` / `ma10_volume`）或 `get_daily_k_data`（含 `volume`）
  - 当日成交额/换手：调 `get_stock_info`（`amount` / `turn_z`）
  - 分时价格与主力：调 `get_stock_minute_trendline`（`y1` 涨跌 / `y2` 主力 / `fund_trend` / `fund_divergence`），**该接口无分时成交量字段**，分时"量"需通过日级成交量 / 成交额间接推断

### 0.8 轮动预期差参与（新冒头方向 + 次日观察验证）

> **动机**：方向确认滞后于方向启动 —— 盘面分析把方向升级为"进攻方向"时，核心标的往往已 7%+ 高位或涨停；"全部条件核齐再买"到手的全是接盘位，"等方向走强再买"买到的是后排跟风。轮动节奏与预期差的唯一官方入口：**盘中** `hot_rotation_analysis.emerging_sectors[]`（新冒头方向），参与方式不是放松纪律，而是**用首笔小仓试错换时间上的左侧**（§2.4 分笔建仓的思路扩展到 Day 1）。（原隔夜入口"复盘台账 → 次日自选池"已随"复盘不做推演"停用，见 §0.8.2；方向连续强势天数的事实记录保留在复盘 `rotation_ledger`，供 §2.3 量化判定用）
>
> **状态机 gating（市场层，先于本节一切参与规则）**：**主升态**——按本节原规则全量适用；**震荡态**——**关闭 §0.8.1 Day 1 追涨通道**（Day 1 追涨的本质就是追当日领涨，与战法三"禁追当日领涨"冲突），保留昨日强势方向企稳后的买点 2/4 参与；**防守 / 预备态**——仅记录观察、不开仓（事实记录照常写）；**冰点态**——一切盘中开仓统一走战法一试错通道：通道 A 冰中博弈（当帧短线 ≤25 + 冰中突围要件）或通道 A2 早盘拉起博弈（9:36~11:00 当帧短线 >25 + 拉起强度三件套），均叠加四层矩阵 ②③④，见 `10-ice-point.md`；§0.8.1 常规 Day 1 通道不单独适用。
>
> **执行节奏（按板块分层，不搞全局时钟一刀切；两类买点见 §二 二元总纲——①题材刚启动跟风、②分歧转一致优先龙头）**：
> - **昨日强势板块（Day 2+：昨日已在进攻名单 / 已发酵方向）→ 今日不急追**：等该板块当日充分释放风险（回踩 / 分歧后**企稳**：板块未从进攻名单消失且 `vs_prev_analysis` 未报降级 + 个股分时回踩关键支撑不破、企稳，§0.6 分时判读）再按买点 2/4 参与。典型在 10:00 前后完成首波释放，**以企稳信号为准，不机械等时钟、也不得在板块未企稳时抢跑**
> - **新启动方向（Day 1 / 新冒头当日确认）→ 不设观察期**：新方向没有昨日获利盘，等它"释放风险"反而等来涨停；emerging 双确认达标即可 Day 1 试错（§0.8.1）
> - **午后（13:00~14:30）主做水下低吸**：上午错过 / 盘中分歧回踩的水下票（`zdf` -5%~0%）是下午主战场——买的是"方向仍有预期的水下分歧"，**不追高**（水上 > +3% 下午不再追，§2.2）
> - **两类买点贯穿始终（§二 二元总纲）**：①题材刚启动时买入（买不到龙头可考虑跟风）；②题材分歧转一致时买入（优先龙头 / 最强势股）。其余状态不买：分歧中无转一致证据不抄底、加强段不追高、**再分歧 = 退潮预警**（兑现准备，不参与）
> - 参与优先级：题材刚启动（Day 1）≈ 分歧转一致 > 其余状态（首次分歧观察等待、加强段只持仓不追、再分歧退潮预警不参与）

### 0.8.1 新冒头方向当日参与（emerging_sectors → Day 1 买点 5；**仅主升态适用**——震荡 / 防守 / 预备 / 冰点态按 §0.8 状态机 gating 关闭）

**方向证据（两条同时满足才算"当日资金确认"，量化主证见 §2.3 防臆想纪律）**：

1. **风向标验证（量化主证）**：该方向 `key_stocks[]` 中 **≥ 2 只当日 `zdf > 3%`**（集体上攻，排除单票脉冲；`zdf` 为代码查表填充的数值字段，非 LLM 输出），且候选个股具备起爆资格（近 3 日累计涨幅 < 15% 且非连续 3 日收阳，`get_daily_k_data` 日线判定——旧题材延续不是窗口 ①）
2. **信号语义（辅助）**：`emerging_sectors[].signal` 语义显示**当日**有实际资金动作（涨停 / 流入 / 放量信号）——**仅辅助增强，量化要件缺失时不得单独参与**；`watch_reason` 同为辅助不单独构成证据

**个股条件（方向确认后逐只核验，与 §2.2 / §2.3 同强度，不降门槛）**：

- 与该方向同板块归属（`get_stock_info` 的 `hot_categories` / `up_reason` 命中）
- 走 §1.1 六池候选集（`emerging_sectors[].key_stocks` 名单个股**仍不直接进选股**，名单只是方向验证样本）；趋势形态达标（close > MA5 且 MA5 上移）
- 当日 `zdf` 0% ~ 7%（高位红线不豁免）；未涨停（§1.3 板块阈值）
- 分时四信号不否决（§2.2 第 5 条）+ 资金面硬条件（第 9 条：主力净流入 > 0 且换手 ≥ 5%）+ 量价健康（§0.7）
- 题材阶段按 **Day 1**（买点 5）执行，禁止拿 Day 1 追涨规则做 Day 2+ 的票（§2.3）
- §0.1 开仓触发两指标（`sentiment_label` + `sentiment_capital_alignment`）照常生效——禁开仓条件同时满足时新冒头参与同样禁止

**仓位与执行**：按 §2.4 分笔 —— 首笔试错 ≤ 目标仓位 1/2（`zdf` 0%~5% 即可进场，**不要求**"完整持续放量上攻形态"核齐）；持续放量上攻 / 量价齐升 / 突破前高出现再补足。新启动方向**不设早盘观察期**，当日确认达标即可试错（§0.8 执行节奏：只有昨日强势板块 Day 2+ 才需要等当日风险释放）。

## 一、选股筛选

### 1.1 候选集（六池合并：趋势三池 + 主力净流入榜 + 成交额榜 + 小时热度榜）

**六个来源合并去重**为统一候选集（典型 100~150 只），筛选标准对**所有来源一致**（形态这道门槛照常卡，见下文"两类来源的形态保证不同"）：

| 池 | 调用 | 字段 | 覆盖范围 |
|----|------|------|----------|
| 创业板强趋势 | `get_strategy_trend_stocks 6` | code/name/zdf/price/turn_z/amount/main_amount/value_z_str/intraday/hot_categories | 10 日内涨幅 > 7%，创业板，非 ST |
| 创业+科创大趋势 | `get_strategy_trend_stocks 10` | 同上 | 15 日内 > 9%，涨幅 > 3%，覆盖创业+科创板 |
| 沪深主板强趋势 | `get_strategy_trend_stocks 7` | 同上 | 沪深主板强趋势 |
| 主力净流入榜 | `get_main_inflow_top` | code/name/zdf/main_amount | 主力净流入前 20 |
| 成交额榜 | `get_amount_top` | code/name/zdf/amount/main_amount/turn_z/intraday | 当日成交额前 30 |
| 小时热度榜 | `get_hourly_hot_top` | code/name/zdf/main_amount | 小时热度榜前 30（按热度排名） |

> **两类来源的形态保证不同（核心机制，"筛选标准不变"的落地）**：
> - **趋势三池（6/10/7）**：入库已保证趋势形态（站上 5 日线 + MA5 上移）+ 间距发散 + 股性活跃（接口隐含过滤，标准见 §1.2 接口隐含过滤项）→ 命中即可直接判买点
> - **主力净流入榜 / 成交额榜 / 小时热度榜**：**只**保证"有主力资金关注 / 成交活跃 / 市场热度"，**不保证趋势形态**。这三池是"种子池"，用于捕获**尚未进趋势池**的实时强势 / 突发放量 / 人气聚拢标的（趋势池有入库刷新滞后）。命中后**必须**用 `get_daily_k_data`（验趋势向上：close > MA5 且 MA5 上移）+ `get_stock_info`（板块归属 / 换手 / up_reason）补验趋势形态，**形态不达标即剔除** —— 这道形态门槛与趋势三池完全一致，只是补验方式不同，**不降低标准**。主力净流入榜 / 小时热度榜缺 `turn_z` 等字段时同样用 `get_stock_info` 补齐

**取数方式（六池全拉合并，不存在"主池优先、其余兜底"）**：

- 六个池**全部拉取**，按 `stock_code` 合并去重为统一候选集，**不存在"主池不足才补"的降级逻辑**
- 合并后在统一候选集上做：①剔除撤退方向个股 ②剔除已涨停（不打板）③**主力净流入榜 / 成交额榜 / 小时热度榜来源补验趋势形态**（趋势三池跳过，入库已含）④按 §二 判定买点 ⑤结合 §0.2 活跃方向做**仓位权重参考**
- 合并候选集经①~⑤过滤后无可买标的 → 输出"无候选标的"并按 §0.1 两指标联动 + §三 止损止盈继续执行（**不**跳过持仓检查，**不**静默空仓）

**约束**：
- 选股池**只来自上述六个接口**。**不**从盘面 `attack_directions` / `attack_sectors.key_stocks` / `get_hot_spot_components` / 连板梯队等任何来源选股
- 候选池**不**做活跃方向归属验证。候选票只要同时满足①不在 `retreat_directions`（已撤退方向，红线 0%）②不在四类股（下跌趋势 / 心电图 / 无题材 / 无放量涨停；趋势三池接口入库隐含过滤，主力净流入榜 / 成交额榜 / 小时热度榜来源命中后随趋势补验一并用 `get_daily_k_data` + `get_stock_info` 核四类）③趋势形态达标（趋势三池入库已含；主力净流入榜 / 成交额榜 / 小时热度榜来源按上文补验）④出现 §二 买点，即可买。**不**要求标的必须落在盘面活跃方向名单内
- **个股取舍由趋势形态 + 买点 + 纪律自主判定，不查盘面活跃方向名单**。盘面活跃方向（方向名）有参考价值，但其下个股名单只是盘面论证方向用的**样本**，**有偏且不完整** —— 形态合格、有买点但不在名单内的标的，同样可以买
- **单只仓位统一上限 ≤ 30%**（心法 §五 仓位红线），具体多少由买点质量、距止损位空间、`risk_warnings` 提示的追高风险**自行研判**：买点位置理想、空间充足给满 30%；尾盘追高、位置偏高则主动收敛，但收敛依据是**位置与风险**，不是**名单归属**（也**不**按来源池分档：趋势三池与主力净流入榜 / 成交额榜 / 小时热度榜来源，仓位上限一致）。目标仓位按 **§2.4 分笔建仓**执行（首笔试错 ≤ 目标 1/2，强确认后补足），不一次性满仓成交
- 龙头是心法层面的优先目标（辨识度最高、带动性最强），龙头无买点时退而求其次做活跃方向内的中军 / 活跃标的
- 趋势三池候选已通过四类股过滤（接口入库隐含完成）；主力净流入榜 / 成交额榜 / 小时热度榜来源命中后随趋势补验一并用 `get_daily_k_data` + `get_stock_info` 核四类股（下跌趋势 MA5 / 分时心电图 / `hot_categories` 无题材 / 日线放量涨停史——全部维度均可数据核验）

**口径说明**：`strategy_id=10` 对应 `app/compute/strategies/strategy_jrqs_dqs.py`（"大趋势"：创业板或科创板、涨幅 > 3%、15 日内 > 9%）。

### 1.2 龙头套利专项（活跃方向内中军 / 活跃股补涨）

> **触发场景**：龙头（板块辨识度最高的标的）已涨停 / 当日涨幅 > 7% 高位 / 错过买点 → 资金溢出到同方向同板块中军 / 活跃股的跟随补涨机会。
>
> **边界红线（方向 / 资金面 / 位置 / 买点类型）见心法 §4.3**。本节是执行层细化 —— 明确四要素联合判定 + 优先级排序，避免把"任何同方向上涨的股"都当成套利。

**四要素联合判定（缺一不可，红线见心法 §4.3）**：

| 要素 | 条件要点 | 验证方式（策略执行层） |
|------|------|----------|
| **① 方向归属** | 同方向同板块 / 主营细分重合 | `get_stock_info` 取 `hot_categories` + `up_reason` 与龙头方向对比 |
| **② 资金面硬条件** | 主力净流入 > 0 且 换手 ≥ 5% | 候选集 `main_amount` > 0 且 `get_stock_info` 取 `turn_z` ≥ 5（§0.5） |
| **③ 位置红线** | 当日涨幅 ≤ 7% | 候选股 `zdf` 直接判定 |
| **④ 买点类型** | 分时承接 / 突破超预期买点 | 分时回踩均价线不破后快速拉起 / 放量突破前高（见 §二） |

**优先级排序（与其它候选冲突时）**：

```
低吸区龙头股（当日涨幅 -3% ~ +3% + 龙头）
  > 强势可承接区套利（当日涨幅 3% ~ 7% + 同方向中军 + 资金净流入 + 分时承接 / 突破买点）
  > 跟风股（不评估）
```

**禁止的套利**：
- ❌ 跨方向套利（"AI 算力龙头涨停 → 买半导体方向"等）
- ❌ 资金面流出套利（"主力 -X 亿但我看好"）
- ❌ 当日涨幅已 > 7% 的位置破红线套利
- ❌ 跟风脉冲套利（"龙头封板带动同板块脉冲 3-5% 但无独立逻辑"）

**判定流程**：
1. **识别龙头**：板块内辨识度最高的标的（不依赖盘面标记）= 当日涨幅最高 + 主力流入最强 + 市值 / 流通市值前列
2. **龙头是否有买点**：当日涨幅 ≤ 7% + 满足 §二 买点之一 → **直接买龙头**（优先级最高）
3. **龙头无买点**（涨停 / 涨幅 > 7% / 错过买点）→ 进入套利评估池
4. **套利评估池筛选**（四要素联合）：①同方向 ②主力净流入 + 换手 ≥ 5% ③涨幅 ≤ 7% ④分时承接 / 突破买点
5. **未命中任一要素** → 输出"无可套利标的"

**接口隐含的过滤项**（候选集入库时已保证，**不重复校验**）：

| 过滤项 | 入库筛选标准 |
|--------|--------------|
| 趋势 | 站上 5 日线（close > MA5）且 MA5 上移 |
| 股性 | 近 120 个交易日内至少 1 次涨停 |
| 形态 | 15 日内阳线多于阴线 + 近 10 日涨幅 > 7% |
| 基本面 | 非 ST、无可转债、自由流通市值 > 30 亿 |

> 候选集由定时任务刷新，存在滞后。盘中若发现候选股临盘异常（突发破位、停牌），用 `get_stock_info` 单票兜底，不维护静态过滤表。

### 1.3 已涨停判定（区分板块）

候选股代码前缀决定涨停板阈值：
- 主板（`60` / `00` 开头）：`zdf ≥ 9.9` → 已涨停（不打板）
- 创业板（`30` 开头）/ 科创板（`68` 开头）：`zdf ≥ 19.9` → 已涨停（不打板）
- 阈值不能统一为 `zdf ≥ 9.9` —— 会误杀创业板 / 科创板 10-19% 的强势未封板股

## 二、买点规则（不打板、不接力、只做超预期）

> 术语定义（首次爆发 / 次日分歧 / 持续发酵 / 健康回踩 / 高位 / 低吸买点等）见心法 `memory/trading-mindset.md`「七、术语字典」。本节为心法的策略落地，只写可执行规则与阈值。

**统一原则**：

**二元买点总纲（一切跟随题材节奏，不固定死；心法 §2.3）**：

题材的典型节奏是状态机：**启动 →（加强）→ 分歧 → 分歧转一致 →（加强）→ 再分歧 = 退潮预警**。分歧不必然转一致（可能直接退潮）；一致加强后的再分歧是退潮开始而非新买点。本战法**只有两类买点**：

1. **题材刚启动时买入**（买点 5，Day 1 / 新冒头当日确认，§0.8.1）：第一次发现题材启动时先跟风买入——**买不到龙头可考虑方向内跟风标的**，分笔小仓试错，**不等强势**（等涨停潮出现只剩后排）
2. **题材分歧转一致时买入**（买点 2 / 3 / 4）：题材经历分歧后重新走向一致的时点——**量化要件**（§2.3 事件判定表）：**已经历分歧**（昨日日线收阴 / 收跌 / 冲高回落，或台账记录昨日分化）**且当日转一致证据**（板块风向标 `key_stocks` ≥ 2 只 `zdf > 3%` 集体上攻 + 个股当日反包：当前价 > 昨日最高 + 板块 ∈ attack 名单判等；`evidence` / `vs_prev_analysis` 等文本仅辅助）。**优先上龙头或最强势的股**（经过分歧换手，龙头辨识度与筹码结构最优）：放量反包突破（买点 3）是转一致的确认形态；分时承接（买点 2）是转一致日的盘中形态；分歧尾声、转一致信号初现时的低吸（买点 4）是窗口 ② 的左侧试错部分

**除此之外一律不买**：分歧中**无转一致证据不预判抄底**（分歧可能直接退潮）；一致加强后的延续段不追高（龙头已辨识，追高易买在加强末端）；**再分歧 = 退潮预警**——不参与，持仓进入兑现准备（§3.0 环境分层减仓）；退潮途中不抄底。**早盘高开不构成独立买点**：昨日强势板块（Day 2+）早盘不急追，等当日充分释放风险（板块回踩 / 分歧企稳，§0.8 执行节奏）；高开信息只作为回调止跌判定（买点 2 / 4）的**辅助证据**——高开后回踩昨收 / 均价不破企稳 = 承接更强的超预期形态：

- **买点 2（分时承接超预期）**：盘中任何时点都成立；**可用于龙头套利场景**（同方向中军分时回踩均价线不破后快速拉起，伴随成交量持续放大）
- **买点 3（突破超预期）**：盘中任何时点都成立；**可用于龙头套利场景**（同方向中军放量突破前期高点 / 整理平台，成交量 > 近 5 日均量 1.5 倍）
- **买点 4（低吸）**：见 §2.2，适用于首次分歧尾声（窗口 ② 左侧试错）或一致加强段的健康回踩（§2.3 状态机），盘中任何时点都成立
- **买点 5（题材首次爆发追涨）**：见 §2.3，仅适用于题材首次爆发（Day 1）且资金确认阶段，zdf 0% ~ 7%，分时持续放量上攻，不打板

| 优先级 | 买点类型 | 条件 | 适用场景 |
|--------|----------|------|----------|
| 2 | 分时承接超预期 | 开盘后分时回踩不破均价线或前日收盘价，快速拉起，成交量持续放大 | **龙头套利**（同方向中军分时承接）/ 低吸区龙头股 |
| 3 | 突破超预期 | 放量突破前期高点/整理平台，成交量 > 近 5 日均量 1.5 倍 | **龙头套利**（同方向中军突破前高）/ 低吸区龙头股 |
| 4 | 低吸（见 §2.2） | 首次分歧尾声或一致加强段的健康回踩，缩量回踩关键支撑，zdf 范围按阶段区分 | 分歧尾声左侧试错 / 一致加强段收敛参与 |
| 5 | 首次爆发追涨（见 §2.3） | 题材首次爆发（Day 1），资金确认，zdf 0% ~ 7%，持续放量上攻，不打板 | 新题材启动跟随 |

**纪律**（来自心法，不可妥协）：
- 已经涨停 → 不追
- 已经连板 → 不追
- **当日涨幅 > 7%（接近涨停或连板）→ 一律视为高位，不追**（不区分板块；心法 §4.3 套利位置红线）
- **题材首次爆发追涨例外**：Day 1 资金确认阶段，zdf 0% ~ 7% 可追，但禁止打板，且必须满足 §2.3 量价条件
- 错过买点 → 放弃，等下一个
- 买入后立即设止损；不设止损 = 不买入
- **套利标的必须满足 §1.2 四要素联合判定**（方向归属 + 资金面 + 位置 + 买点 2/3）

### 2.2 低吸买点

**核心定位**：低吸是"**攻击方向内部**的强势股回踩机会"，不是"冷门股抄底"，也不是"高位股追涨"。

**判定条件（正向买入理由 + 前置否决过滤两组）**：

> 第 5、6、7、8、9 条为前置否决过滤：任一成立即否决买入，但**不是买入理由，禁止写入买入 reason**；买入 reason 只写第 1~5 条（§7.1）。

**① 正向买入理由（全部满足）**：
1. **属于近期攻击方向**（命中 `final_analysis.attack_directions[].direction` ∪ `hot_rotation_analysis.attack_sectors[].sector`）
2. **趋势向上**：close > MA5（站上 5 日线）且 MA5 上移；**不要求站上 10 日线**（10 日线仅用于趋势止损，见 §三）
3. **回踩幅度合理**：当前 `zdf` 在 **-5% ~ +3%** 区间；其中首次分歧（Day 2）可放宽至 -5% 水下低吸，多日分歧 / 一致加强段（Day 3+）收紧至 -3% ~ +3%。**不接 -5% 以下的飞刀**（跌幅过深说明承接失效）
4. **板块仍强**：当日盘面进攻方向强度未变弱（`vs_prev_analysis` 未报告该方向降级）
5. **量价健康（§0.7）**：出现**上涨缩量回踩**或**持续放量上攻**或**量价齐升**之一；买入前必须确认未出现放量滞涨 / 放量冲高回落 / 放量下跌 / 缩量阴跌等衰竭信号

**② 前置否决过滤（任一成立即否决买入）**：
5. **分时未现卖点（硬前置，不可跳过）**：买入前**必须**对候选股调 `get_stock_minute_trendline` 采分时（涨跌 `y1` + 主力 `y2`），按 §0.6 判四信号（放量滞涨 / 长上影 / 走势与板块背离 / 资金背离），任一成立即**否决买入** —— 与持仓监控（教训 A.7）同等强度，禁用 `zdf` 快照 / K线代替分时判定（教训 A.8）
6. **资金-涨幅不背离**：主力大额净流入（量级显著，如 > +1 亿）但 `zdf` 压在低位（资金量级与涨幅明显不匹配）→ "钱进价不涨"的派发嫌疑，**优先怀疑派发而非低吸**，需第 5 条分时确认是真回踩还是冲高回落（心法 §4.5）
7. **趋势衰竭 / 非健康回踩**：
   - 若标的近 3 个交易日累计涨幅 ≥ 15%，或连续 3 日及以上收阳上涨，视为短线趋势已充分演绎。此时仅因日内从高位回落到 -5%~+3% 区间，**不再自动视为**"健康回踩"，而更可能是趋势末端的高位震荡 / 早盘资金派发后的余温
   - 买入前必须额外确认：**当前时点正处于当日深度回踩的末端或刚企稳**，即当前价格曾跌破昨日收盘价或 MA5 后获得明显承接，且回拉时伴随缩量或资金回流；若价格已大幅回升（如当前涨幅 > +1% 且已从日内低点反弹超过 2%），则禁止买入
   - `y2` 主力资金序列呈"先入后出"形态（前段净流入上行、后段持续回落且末值显著低于日内峰值）且近 3 日累计涨幅 ≥ 15% 时，**直接否决**买入（早盘流入午后流出，与趋势衰竭共振，派发概率极高）
8. **题材阶段错配**：不属于 §二 二元总纲任一窗口时**禁止买入**——即不属于窗口 ①（题材启动 Day 1 跟风，买点 5），也不属于窗口 ②（分歧转一致：转一致确认日买点 2/3，或分歧尾声转一致信号初现的买点 4 左侧试错）时，一律不买（其他时候保持谨慎）
   - 若无法明确判定题材阶段 / 事件（§2.3 量化要件），按"无法判定 = 不买"处理（§2.3 防臆想纪律）；拿不准则放弃
9. **资金面硬条件（与套利 §0.5 统一，教训 A.11）**：买入前**必须**调 `get_stock_info <code>` 取 `amount_main`（主力净额）与 `turn_z`（换手率）。**主力净流出（`amount_main` < 0）即一票否决**——资金不承接，不论形态多好、方向多对、买点多理想都不买；换手率 `turn_z` < 5% 说明活跃度不足、资金参与度低，低吸题材股同样否决。`amount_main` 缺位时按 §0.5 三级兜底口径取数（候选集 `main_amount` → `amount_main` → 分时 `y2` 末值），全部缺位 = 无法判定 = 不买。与套利 §0.5 资金面红线对齐，**不因"龙头低吸"豁免**；"无背离"（`fund_divergence == "normal"`）**不等于**主力净流入，禁止拿它当资金承接证据

买入 reason 必须显式说明：题材阶段 / 事件（§2.3 状态机：启动 Day 1 / 首次分歧 / 分歧转一致 / 一致加强 / 再分歧退潮，及所属二元窗口）、近 3 日累计涨幅、量价信号（上涨缩量回踩 / 持续放量上攻等）、是否处于回踩末端 / 刚企稳、为何判定为真承接而非追高末端。

**时间窗口（按板块分层，§0.8 执行节奏）**：
- **昨日强势板块（Day 2+）早盘不急追**：等该板块当日充分释放风险——回踩 / 分歧后**企稳**（板块未从进攻名单消失、`vs_prev` 未报降级 + 个股分时回踩关键支撑不破、企稳）再按买点 2/4 参与；典型在 10:00 前后完成首波释放，**以企稳信号为准，不机械等时钟，也不得未企稳抢跑**。**禁止以竞价数据（竞价量等）作为任何判定依据**（§0.8.2 数据边界）
- **新启动方向（Day 1 / 新冒头当日确认）不受观察期限制**：当日确认达标即可 Day 1 试错（§0.8.1）——新方向无昨日获利盘，死等释放反而等来涨停
- **早盘回踩承接**：10:00-11:30 是 Day 2+ 回踩买点的典型窗口（强势股早盘冲高后回踩均价线 / 前日收盘；早盘高开后回踩不破企稳 = 承接更强的超预期形态，作辅助证据）
- **午后水下低吸（13:00-14:30，主战场）**：上午错过 / 盘中分歧回踩的水下票（`zdf` -5%~0%）——方向仍在当日进攻名单 / 未进撤退名单 + 缩量回踩关键支撑企稳 + 实测主力净流入 > 0（水下且有资金承接 = 真分歧而非崩塌，§2.2 第 9 条资金面红线不豁免）→ 按买点 4 水下低吸；**下午不追高**（水上 > +3% 下午不再追）
- **尾盘 14:30 之后**：非低吸窗口、不追涨；**唯一例外：冰点战法尾盘试错通道（`10-ice-point.md`，且以 `next_day_channel_open` 预计算字段为资格前提）**

**纪律**：
- ❌ "低吸" ≠ 抄底下跌趋势（心法 §4.1：MA5 下行不接飞刀）
- ❌ "低吸" ≠ 在冷门题材 / 无主流资金关注的股上买入
- ❌ 低吸买点出现时不调高单只仓位上限（仍按心法 §五 ≤ 30%）

### 2.3 题材阶段判定与买点匹配

> 本条是心法 §2.3「题材生命周期与持续性纪律」的策略落地。术语定义（首次爆发 / 次日分歧 / 持续发酵 / 健康回踩）见心法 `memory/trading-mindset.md`「七、术语字典」。任何买入必须先回答"题材当前处于哪个阶段 / 事件（二元总纲的窗口 ① 还是窗口 ②）"，**不能拿一个买点套所有阶段**。

#### 题材阶段判定（状态机：启动 →〔加强〕→ 分歧 → 分歧转一致 →〔加强〕→ 再分歧退潮）

> **防臆想硬纪律**：阶段判定以**量化主证**为准（数值字段计数 / 日线 bar 判等 / 名单判等 / 本地台账）；`evidence` / `signal` / `watch_reason` / `vs_prev_analysis` / `action_advice` 是 **LLM 自由文本，一律只作辅助**——与量化结论同向时增强信心，**量化要件缺失时不得单独触发任何买卖**（无法判定 = 不买，宁错过不臆想）。

**量化主证（三条腿）**：

1. **个股日线**：调 `get_stock_daily_history <code>` / `get_daily_k_data <code>` 取近 5 日 bar（open / high / close）：
   - **起爆资格**：近 3 日累计涨幅 < 15% 且非连续 3 日收阳（区分"新启动"与"旧题材延续"，后者不是窗口 ①）
   - **分歧证据**：昨日 bar 收阴 / 收跌（close < 前日 close）/ 冲高回落（昨日 high − close ≥ 4%）之一
   - **反包证据**：当日当前价（`get_stock_info` 实时 / `get_stock_minute_trendline` 末值）**> 昨日 bar 最高价**
2. **板块风向标计数**：当帧 `attack_sectors[]` / `emerging_sectors[]` 中该板块 `key_stocks[].zdf`（代码查表填充的数值，非 LLM 输出）逐只计数：
   - **集体上攻**：≥ 2 只 `zdf > 3%`（或半数以上 > 0 且最高者 > 5%）
   - **分化**：涨跌互现且 > 3% 者最多 1 只
   - **集体走弱**：半数以上 `zdf < 0`
   - 板块强度辅助：`today_zt ≥ 3` 或 `today_inflow` 显著为正（可选字段，**缺位时跳过，用 key_stocks 计数兜底**）
3. **板级历史（本地台账）**：读取路径 `data/daily-summary-{昨日}.json` 的 `next_day_plan.rotation_ledger`（方向生命周期台账，21 点复盘写入；调度器对落地 json 保留 10 个自然日，跨周末 / 节假日的昨日台账可用）。台账中**连续强势天数**是**滚动累计字段**——每日复盘更新（昨日仍强则 +1，走弱 / 撤退归零），因此盘中判定**只依赖昨日一份**、不回溯更早文件。该方向"此前已连续强势 N 日"以台账记录为权威源（历史帧服务端不提供）；昨日台账缺记录 / 文件不存在（调度器断档等）→ 视为无法确认"此前强势"，再分歧预警判定降级为普通分歧处理（不误判退潮、也不臆想强势）

**事件判定（量化要件组合）**：

| 事件 | 量化要件（须同时成立） | 文本辅助（不单独构成） |
|------|------------------------|------------------------|
| **启动（Day 1）** | 个股起爆资格 + 板块风向标集体上攻（§0.8.1 双确认同源） | evidence / signal 语义"今日首次""新晋方向"；vs_prev 未报告该方向此前已在进攻名单 |
| **首次分歧** | 个股分歧证据（昨日日线）+ 板块风向标当日分化（或该板块从 attack 名单降入 observe / 名次明显下滑） | vs_prev 语义"分化 / 走弱"；evidence 强度描述转弱 |
| **分歧转一致** | **已经历分歧**（个股昨日日线分歧证据，或台账记录昨日该方向分化）+ **当日转一致证据**：板块风向标集体上攻 **且** 个股当日反包（当前价 > 昨日最高）**且**板块 ∈ 当日 attack 名单（判等） | evidence / vs_prev 语义"反包 / 集体走强 / 分歧转一致" |
| **再分歧（退潮预警）** | 台账记录该方向此前已连续强势 ≥ 2 日（一致加强段）+ 当日板块风向标集体走弱 **或** 板块从 attack 名单消失 | vs_prev 语义"走弱 / 降级 / 逆转"（§3.0 已有触发源，同向增强） |

> **数据限制**：任一量化要件字段缺位（如 key_stocks 为空、日线接口失败）→ 该事件**无法判定 → 不买**，不降标准、不用文本顶替。`today_zt` / `today_inflow` 为可选字段，缺位时跳过该选项，不减低其它要件标准。

#### 阶段与买点匹配（二元总纲的落地）

| 阶段 / 事件 | 判定特征（量化要件，见上方"事件判定"表） | 可用买点 | 涨幅区间 | 仓位态度 |
|------|----------|----------|----------|----------|
| **启动（Day 1）** | 个股起爆资格（近 3 日未明显上涨）+ 板块风向标集体上攻 | **买点 5：跟风买入**（买不到龙头可考虑方向内跟风标的） | 0% ~ 7% | 分笔试错，禁止打板 |
| **首次分歧（Day 2，或任意日首次分化）** | 个股昨日日线分歧证据 + 板块风向标当日分化 | **观察等待为主**；仅分歧尾声 + 转一致信号初现（个股率先反包承接）→ **买点 4 左侧试错** | -5% ~ +3%（多日分歧后收紧至 -3% ~ +3%） | 试错仓，**禁止无转一致证据的预判抄底**（分歧可能直接退潮） |
| **分歧转一致（事件，任意日）** | 已经历分歧 + 板块风向标集体上攻 + 个股当日反包（当前价 > 昨日最高）+ 板块 ∈ attack 名单 | **买点 2 / 3，优先龙头或最强势股**（分歧换手后龙头辨识与筹码最优） | 按个股反包 / 突破位判定 | 窗口 ② 主仓位，确认后按 §2.4 补足 |
| **一致加强（转一致后的延续段，Day 3+）** | 台账记录转一致后板块继续集体走强 ≥ 1 日 | **只持仓不追高**——龙头已辨识，追高易买在加强末端；仅回踩清晰且转一致逻辑仍在时可按买点 4 收敛参与 | -3% ~ +3% | 仓位收敛，没有清晰回踩则放弃 |
| **再分歧 = 退潮预警** | 台账记录此前已连续强势 ≥ 2 日 + 当日板块风向标集体走弱或从 attack 名单消失 | **禁止买入**；持仓进入兑现准备 | — | §3.0 环境分层减仓 |
| **退潮** | 进撤退名单 / vs_prev 报告退潮 | **红线 0%** | — | 清仓（§0.2） |

#### 执行纪律

- **分歧不必然转一致**：首次分歧后必须等**转一致证据**出现才参与（窗口 ②），无证据的分歧中预判抄底 = 接飞刀（心法 §4.1）
- **一致加强后的再分歧 = 退潮开始**，不是第二个回调买点——不参与，持仓兑现准备；轮动的正确参与是等**下一个题材启动**（窗口 ①）或**下一个方向的分歧转一致**（窗口 ②），不在退潮题材里反复抄底
- **不能拿 Day 2 的低吸规则去做 Day 3+ 的票**：Day 3+ 必须有更清晰的缩量回踩或持续放量上攻，否则放弃
- **不能拿 Day 1 的追涨规则去做 Day 2+ 的票**：Day 2+ 还从 0% 以上追涨，属于追高，除非回到当日回踩末端
- **买入 reason 必须写明阶段 / 事件**："题材启动跟风（Day 1）"、"分歧转一致（窗口 ②，含转一致证据）"或"分歧尾声左侧试错（窗口 ② 左侧）"，并给出判定依据
- **其他时候保持谨慎**：不属于窗口 ① / ② 且量价不健康的，一律不评估、不买入

### 2.4 分笔建仓（试错 + 确认补足）

> **动机**：低吸区优先级最高，但"全部条件确认后才买"会把成交点推高到强势区（确认成本右移——条件核齐时价格已走）。分笔结构用**首笔试错对冲晚确认**：初部确认即小仓进场，强确认再补足，买点自然左移；T+1 当日不可卖，首笔减半即单笔风险减半。**Day 1 追涨同理**：完整"持续放量上攻"形态核齐时价格常已近 7% 红线，首笔在 0%~5% 左侧进场、强确认再补足（§0.8.1）。
>
> **状态机 gating**：**补足笔视同新开仓过层①**（状态机索引四层矩阵）——补足时点市场层不允许开仓（防守 / 预备 / 冰点）→ 不补足、只持有（不加仓不构成卖出信号，去留按 §三 止损止盈）；卖出动作不受状态机限制。

**执行规则**：

| 阶段 | 触发条件 | 仓位动作 |
|------|----------|----------|
| **首笔试错（低吸）** | §2.2 ①组**全部达成**（五条静态条件：方向 / 趋势 / 回踩幅度 / 板块仍强 / 量价健康——回踩发生中即可核验，**不要求**买点 2/3 的动态拉起 / 突破确认），且资金面硬条件（§2.2 第 9 条：主力净流入 > 0 + 换手 ≥ 5%）达标、分时四信号否决（第 5 条）通过、②组前置否决全部不成立 | 建首笔 ≤ 目标仓位的 **1/2**，立即设止损 |
| **首笔试错（Day 1 追涨）** | §0.8.1 新冒头方向当日确认（或 §2.3 Day 1 板块证据）+ 候选 `zdf` 0%~5% + 资金面硬条件（§2.2 第 9 条）达标 + 分时四信号否决（第 5 条）通过 + 量价健康（§0.7）——**不要求**完整持续放量上攻形态核齐 | 建首笔 ≤ 目标仓位的 **1/2**，立即设止损 |
| **建仓（分歧转一致确认，窗口 ② 右侧）** | §2.3 分歧转一致**量化要件全部成立**（昨日分歧证据 + 当日风向标集体上攻 + 个股反包当前价 > 昨日最高 + 板块 ∈ attack 名单），买点 2 / 3 本身即为强确认，优先龙头或最强势股 | 买点 2/3 已是强确认，可按目标仓位一次建足（合计 ≤ 30% 心法红线），立即设止损；资金面硬条件（§2.2 第 9 条）与分时四信号否决（第 5 条）照常执行 |
| **确认补足** | 下列任一强确认出现：放量突破前高 / 整理平台（买点 3）；分时回踩不破均价快速拉起 + 主力持续流入（买点 2）；持续放量上攻 / 量价齐升延续（§0.7） | 补足至目标仓位（合计仍 ≤ 30% 心法红线） |
| **确认不现** | 当日未出现任一强确认 | 试错仓按 §三 个股级纪律独立处理，**禁止摊低成本式加仓** |

**纪律**：
- 首笔与补足共享同一目标仓位预算；试错仓触及固定止损 → 止损离场，不等确认信号
- **不因分笔降低任何一道过滤**：四信号否决、资金面硬条件、趋势衰竭过滤（§2.2 ②组）在首笔前全部照常执行
- 补足笔的买入 reason 单独记录确认信号（§7.1 买卖 reason 不混写）

## 三、止盈止损（环境 → 方向 → 个股三层）

### 3.0 环境分层减仓（第一、二道防线：不等个股回撤才卖）

> **动机**：只看个股回撤信号（四信号 / 利润回撤 / 破位）卖出，是在"价格已经回落"之后滞后离场。题材整体回撤 + 大盘转弱时，**环境走弱先于个股走弱**——个股补跌在即，卖点必须前移到环境层，逢高分批兑现，不等个股回撤触发。

**触发矩阵（全部取盘面字段原值，不自创标签）**：

| 层级 | 触发条件（字段原值） | 动作 |
|------|---------------------|------|
| **环境级** | `final_analysis.sentiment_capital_alignment == "退潮"` | **全部持仓**：停止加仓，逢高分批减仓（首笔约 1/3，2~3 笔完成） |
| **环境级** | `alignment ∈ {"虚热", "强撑"}` **且** `vs_prev_analysis` 报告持仓所属方向走弱 / 降级 / 逆转 | **该方向持仓**：逢高分批减 1/3 ~ 1/2 |
| **方向级** | 持仓板块进入 `retreat_directions` / `retreat_sectors`（§0.2 板块归属判定） | 红线 0%，清仓（原有，最高优先级） |
| **方向级** | 持仓所属方向从 `attack_directions` 名单消失（`vs_prev_analysis` 报告降级） | 同"虚热/强撑 + 方向走弱"行，纳入分批减仓 |

**执行纪律**：

1. **分批逢高，不恐慌一键清仓**：触发当轮执行首笔（约 1/3），其后利用反弹 / 分时相对高位分笔再减，2~3 笔完成——减仓也要卖在相对高位，禁止追着跌卖
2. **红线优先**：减仓途中命中撤退方向红线（0%）或个股固定止损（-5%）→ 剩余仓位**立即执行**，不再等高位
3. **与 §0.1 的边界**：`position_limit` 单独降低**不**触发本节减仓（"不因 limit 降低强卖进攻方向持仓"继续有效）；本节触发源仅限 alignment / vs_prev / 撤退名单三类字段
4. **不以偏概全**（总纲 §5.5）：非持仓方向的撤退 / 风险提示不触发本节；环境级触发（alignment=退潮）作用于全部持仓的仓位态度，方向级触发只作用于该方向持仓
5. 卖出 reason 必须写明触发字段原值（如 `alignment=退潮`、`vs_prev 报告 XX 方向降级`），与个股级 reason（§3.1）区分
6. **T+1 边界**：当日买入（`available_volume == 0`）的持仓当日无法执行减仓 / 清仓，不对其做盘中卖出导向分析（总纲 §3.3）；次日可卖后按当次盘面重新判定，**不预承诺**（总纲 §5.1 第 4 条）

**止盈松紧跟随环境（同一框架的对称面）**：

- **环境健康**（`alignment == "共振"` 且持仓方向仍在 `attack_directions`）：底仓以趋势止损（10 日线）+ §0.6 四信号管理，利润保护从"最高点回撤 -5%"放宽为**趋势破位 / 四信号触发再走**——环境 + 方向 + 个股三重强势时让趋势奔跑，不因日内小回撤兑现（心法 §4.5"非强势股少格局"的对称面：强势环境可以格局）
- **环境转弱**（命中本节任一触发）：利润保护恢复"浮盈从最高点回撤 -5%"（§3.1 原阈值），并叠加本节分批减仓——环境不支持格局时收紧兑现

### 3.1 主动评估原则与阈值表

> **定位**：本节是个股级阈值，是与 §3.0 环境级**各自独立生效的第三道防线**——环境信号管"要不要提前减"，个股信号管"形态坏了必须走"，环境级触发时个股级照常生效（§3.0 红线优先），互不替代。

**不止被动等触发，所有止盈维度每轮盯盘都必须主动评估**（评估对象为**可卖持仓** `available_volume > 0`，当日买入 T+1 不可卖的盘中跳过，见总纲 §3.3）—— 不等"破止损位 / 破 10 日线"再动作。**不及预期提前获利了结**是纪律红线，不是事后止损。**优先保住利润，非强势股少格局** —— 出现放量滞涨 / 走势与板块背离即倾向落袋，不死扛等大涨。

> **加速止盈是形态信号，只能从分时序列识别（见 §0.6），禁止用收盘快照价 / 浮亏% 代替**。

| 评估时机 | 评估维度 |
|---------|---------|
| 每轮盯盘 | ① 加速止盈信号（放量滞涨 / 长上影线 / 走势与板块背离，见 §0.6）——**不等触顶才看** |
| 每日收盘 | ② 时间止损（买入后第 3 日评估是否出现预期上涨；冲高回落不算，见 §0.6） |
| 浮盈时 | ③ 目标止盈（+10%）、④ 利润保护（从最高点回撤 -5%）、⑤ 移动止损（+50% 后回撤 -10%） |

| 类型 | 触发 | 执行 |
|------|------|------|
| 固定止损 | 买入价下跌 -5% | 立即卖出 |
| 技术止损 | 跌破买入日最低价或前低 | 立即卖出 |
| 时间止损 | 买入后 3 日内未出现预期上涨（**冲高回落不算预期上涨**，见 §0.6） | 评估后离场 |
| 趋势止损 | 股价跌破 10 日线（MA10） | 立即卖出 |
| 目标止盈 | 浮盈 +10% | 减仓一半 |
| 加速止盈 | 放量滞涨 / 长上影线 / 走势与板块背离（见 §0.6） | 清仓或大幅减仓 |
| 利润保护 | 浮盈从最高点回撤 -5%（环境健康时按 §3.0 放宽为趋势破位 / 四信号再走） | 清仓保护利润 |
| 移动止损 | 单只盈利 > +50% 后回撤 -10% | 清仓 |

> **开盘极端行情止损确认窗口**：开盘大低开 / 秒杀瞬间击穿止损位，**不机械秒割**，给约 15 分钟（9:30-9:45）确认 —— **缩量急跌快速收回 = 恐慌洗盘，不止损；放量跌破买入日最低价 / 10 日线不回头 = 趋势破位，确认止损**。触跌停、放量破 10 日线 → 立即止损不等。（固定止损在开盘极端行情下的执行细则，不废除止损纪律。）

### 3.2 加速止盈信号识别（每轮持仓必判）

> 对每只**可卖持仓**（`available_volume > 0`；当日买入 T+1 不可卖的盘中跳过，见总纲 §3.3）取 `get_stock_minute_trendline`（涨跌 `y1` + 主力 `y2`）+ `get_stock_info`（板块归属），按 §0.6 四信号表判定，任一信号成立即加速止盈 —— **禁用快照价 / 浮亏% 判定**（给不出形态与资金，教训 A.7）。

- **时间止损**：冲高回落（最高 − 收盘 ≥ 4%）不算"预期上涨已现"，触发离场（防"收盘红盘"的伪正向）
- 出现任一异常默认倾向卖出、需明确理由才留（心法 §4.5）

## 七、输出规范

每轮盯盘输出由「盯盘总结标记」起头，后接观点总结 + 一行摘要。**注意：盯盘的"开始/结束"边界由调度日志自动打印，agent 不再重复输出"盯盘开始/盯盘结束"，只用「盯盘总结」标记自己的分析输出**：

```
========== 盯盘总结 HH:MM:SS ==========
（盯盘观点总结）
（一行摘要行）
```

- **盯盘总结标记**：观点总结的标题行，标记本轮分析输出开始
- **盯盘观点总结**：结构化分析结论（见下方板块结构）
- **一行摘要行**：`[柚子 AI] HH:MM | ...` 摘要（见下方格式）

> **标记格式固定**：`========== 盯盘总结 HH:MM:SS ==========`（等号 10 个，时间精确到秒，**逐字采用调度指令注入的「当前时间」**；未注入时先 `date "+%H:%M:%S"` 实测；禁止从 `analyze_time` / 分时 labels / 上轮记忆推算 —— 模型无时钟，自估必臆造）。**不要输出"盯盘开始/盯盘结束"** —— 轮次边界由调度日志负责，agent 重复输出会造成两份重复标记。

> **核心要求**：观点总结**按板块给结论、过程数据作支撑**，禁止把 §五 checklist 的逐项检查过程（"§0.1 两指标联合 / 趋势股池+过滤 / 方向归属核验…"这类流水账检查项表格）直接当输出。读者要一眼看到「观点」，而不是在一堆检查项里自己拼结论。

### 7.1 观点总结板块结构

| 板块 | 内容（先结论，后可验证支撑） | 空值兜底 |
|------|------------------------------|----------|
| **市场判断** | 情绪（`sentiment_label`）+ alignment（`sentiment_capital_alignment`）→ §0.1 开仓资格结论；仓位上限（`position_limit`）；活跃方向；一句话市场核心特征 | —— |
| **持仓个股分析** | 逐只：代码/名称、`zdf`、浮盈、§3.0 环境分层减仓状态（未触发 / 已触发第 N 笔 + 触发字段原值）、§三 止盈止损评估结论、本轮动作（持有/减仓/清仓）。**可卖持仓（`available_volume > 0`）必须带分时形态结论**（§0.6 四信号：放量滞涨/长上影/板块背离/资金背离），禁只用快照价判定；当日买入（可卖量 0）的持仓仅用持仓快照标注"今日买入 T+1 不可卖"+ `zdf` / 浮盈，不调分时接口（总纲 §3.3） | 写"当前空仓" |
| **候选个股分析** | 三池合并去重总数 → 过滤项（已涨停/高位 `zdf`>7%/交易所重点监管禁买名单/撤退方向）→ 进入核验数；逐只取舍结论（代码/名称、`zdf`、命中买点类型或"无买点+原因"、方向归属判定结果）。盘面 `action_advice` 推荐但被纪律否决的龙头在此说明原因（如已涨停不打板、不在三池） | 写"三池合并 N 只，过滤后无符合买点标的" |
| **综合决策** | 本轮最终动作 + 一句话核心原因（可验证事实，非主观判断） | —— |

纪律（观点总结同样受总纲 §5.6「不允许的写法」约束）：

- 情绪/仓位/活跃字段直接采用盘面返回值，**不**自创标签/调档数字，**不**复述 `position_reasoning` 区间
- 候选取舍只报客观事实（`zdf`、买点类型、方向归属判定结果），**不**写"我判断不匹配/我认为不行"等主观话术
- **不**预设未来时点动作；可写"明日需重新评估的检查项"清单（不绑定动作），禁止把 `vs_prev` 信号机械外推为下一时点具体动作
- **不**自拾炸板率/大面家数/破位率/连板高度等指标作为论据
- **买入 reason 与卖出 reason 不得混写（写法红线）**：
  - 买入 reason 只写正向买入逻辑：方向归属 + 买点类型 + 形态/量能事实（§2.2 ①组、§二 买点）
  - 卖出 reason 只写卖出逻辑：止损/止盈类型（§三）、加速止盈四信号（§0.6）、撤退方向（§0.2）
  - 禁止把"分时未现卖点""未触发止损""未现止盈信号""T+1 不可卖"等否决/持有侧逻辑写入买入 reason

观点总结示例（空仓、无买点场景）：

```
【市场判断】情绪偏保守 + 警惕（非撤退）→ 不禁开仓，仓位上限 30%；活跃方向存储芯片/先进封装；大盘系统性风险释放中（锂电崩盘）
【持仓分析】当前空仓
【候选分析】三池合并 19 只去重 → 过滤已涨停 1 / 高位(zdf>7%)5 / 交易所重点监管禁买 2 → 11 只核验；昆仑万维(AI应用,方向不符)/巨人网络(游戏,方向不符)；格科微(芯片✓) zdf+2.88% 但芯片方向降级(§2.2 条件4不满足)；候选股均冲高回落无买点 2/3。盘面推荐华天科技/浪潮信息均 zdf≈10% 已涨停不打板，兆易创新/寒武纪不在三池
【综合决策】空仓不操作（候选股均冲高回落无买点 + 芯片方向降级）
```

### 7.2 一行摘要行（观点总结之后输出）

格式（与总纲 §八 一致）：

```
[柚子 AI] HH:MM | 盯盘 | 阶段:X | 情绪:激进/偏激进/中性/偏保守/保守 | 置信度:X | 活跃:XX | 仓位:NN% | 操作:XX | 持仓:NN只
```

- 时间字段 HH:MM = 调度指令注入的「当前时间」（未注入时 `date` 实测），与盯盘总结标记同源；禁止取 `analyze_time` / 分时 labels 末值 / 自估（总纲 §八「时间取值」硬红线）
- **阶段字段** = `read_regime_state` 输出的 `state_label`（中文映射固定：防守 / 冰点 / 主升预备 / 主升 / 高位震荡；读取失败 / `defensive_reason` 非空按防守处理时输出"防守（状态读取异常）"）—— 值直接取自状态机代码输出，禁止自创
- 情绪字段直接采用盘面 `sentiment_label` 值，**不**自创"主升/回暖/退潮"等标签
- 仓位字段直接采用盘面 `position_limit` 值，**不**自创"5成""3成"等调档数字
- 活跃字段 = `final_analysis.attack_directions[0].direction if final_analysis.attack_directions else "该字段为空"`（仅展示近期活跃方向，不复述 `reason` / `evidence`；缺位时按总纲 §5.2 字段缺位判定）
- 操作字段 = 实际动作；"无操作"也要输出
- **不**输出 `position_reasoning` 的区间/上下沿/微调表述

### 7.3 完整轮次示例（盯盘总结标记 → 观点总结 → 摘要）


### 7.4 复盘输出规范（标记 + 板块 + 摘要）

盘后复盘输出与盯盘对称：由「复盘总结标记」起头，后接 3 个结构化板块 + 一行摘要。**复盘同样用「复盘总结」标记自己的产出，不输出"复盘开始/复盘结束"边界**（边界由调度日志负责）。**复盘不做推演：只分析今日操作与不操作，无次日计划板块**（总纲 §7.2）：

**复盘动作（只做今日分析，不做推演；状态机推进由盘中自愈承担（总纲 §3.1），复盘不再推进）**：

1. 常规复盘（大盘 / 历史 / 热点 / 交易日志 / 盈亏分析，见下）
2. 在 `daily-summary-{date}.json` 落库 `regime_track`（前向数据，进化的燃料；当日 s/d 定格值取自 `market.get_daily_indicators_history --days 1` 当日行，状态字段取盘中 `read_regime_state` 实际读数）：

```
regime_track: {
  date, s, d,                          // 当日收盘双温度（s 缺数记 null）
  state,                               // 当日生效状态（盘中 read_regime_state 实际读数）
  cluster_depth,                       // 当日簇深度（冰点态）
  channel_open,                        // 当日尾盘通道是否开放（晨起判定）
  state_decision,                      // 状态机当日允许的行为（禁开仓/尾盘通道/全量）
  llm_snapshot,                        // 当日 LLM 关键字段快照（sentiment_label / alignment / position_limit）
  contradiction,                       // 状态机 vs 当日层是否矛盾（bool，如主升态但当日禁开）
  actions: [...],                      // 当日操作（对照状态机预期标注：符合/越权/错过）
  t2_eval,                             // 冰点试错 T+2 验证结果（回填，含"验证成立但状态机禁加仓"的独立标注）
  next_day_outcome                     // 次日 s/d 与走势（次日复盘回填）
}
```

```
========== 复盘总结 YYYY-MM-DD ==========

【当日盈亏】（今日盈亏 + 累计 + 交易笔数 + 持仓明细）
【情绪演变】（情绪 / 温度 / 主力净额当日轨迹）
【操作反思】（合规检查 + 纪律执行 + 经验 + 不操作的合理性分析）

[柚子 AI] 复盘 | 盈亏:... | 反思:...
```

- **复盘总结标记**：`========== 复盘总结 YYYY-MM-DD ==========`（等号 10 个，日期取当日交易日）

复盘板块结构（先结论、后可验证支撑，同样受总纲 §5.6 纪律约束）：

| 板块 | 内容 | 空值兜底 |
|------|------|----------|
| **当日盈亏** | 今日盈亏金额（+比例）、累计盈亏；交易笔数；持仓明细（每只代码/名称/浮盈%） | 写"今日无交易" |
| **情绪演变** | 当日情绪/温度/主力净额的轨迹（起→终），点明情绪转折；**只引用盘面字段**（`temperature` / `sentiment` / `main_amount`），**不**自拾炸板率/大面家数等额外指标（总纲 §5.1 第 2 条） | —— |
| **操作反思** | 合规性检查（总仓位 vs 盘面 `position_limit`、单只 ≤30%、同方向 ≤50%、已撤退方向=0）；纪律执行情况；**不操作的合理性分析**（行情好时为何一直不开仓 / 行情不好时为何开仓——对照状态机预期）；可复用经验/教训（对应 `daily-summary` 的 `reflection`） | 写"今日无操作，无反思项" |

完整示例：

```
========== 复盘总结 2026-07-09 ==========

【当日盈亏】今日 +1104.76元(+0.7%)，累计 +58.35%；交易 2 笔；持仓：格科微(688728)+4.05%、华大九天(301269)+0.5%。
【情绪演变】大盘情绪 30→44 修复跃迁，短线温度 30→70 偏激进，主力净额 -785→+269 亿方向反转。
【操作反思】冰点反弹精准加仓，双笔买入合规（单只<30% / 同向<50% / 总仓位 38.6% < 盘面 78%）。

[柚子 AI] 复盘 | 盈亏:+0.7% | 反思:加仓合规
```

> 复盘摘要行格式：`[柚子 AI] 复盘 | 盈亏:+X.X% | 反思:<一句话>`；盈亏取实盘结算值，**不**自创。

### 7.5 总结上报（输出后必做）

每轮总结产出后，**必须**调 `report.submit_summary` 把当轮总结文本同步到后台（写入 `mock_log` 表），供事后回溯 agent 的判断与决策。**每轮盯盘都要上报（含"无操作"轮）**，复盘产出后上报一次。

| 阶段 | 调用 | `content` 取值 |
|------|------|----------------|
| 盯盘（每轮输出后） | `cli.py report.submit_summary watch "<文本>"` | 当轮「盯盘总结标记」+ 观点总结 + 摘要行的完整文本（**含标记**） |
| 复盘（盘后产出后） | `cli.py report.submit_summary review "<文本>"` | 当轮「复盘总结标记」+ 3 板块 + 摘要行的完整文本（见 §7.4） |

**content 必须与当轮终端输出逐字一致**（至少完整包含总结标记、观点总结、摘要行原文）：时间等字段随原文带出，**禁止**在上报文本中改写时间、截断内容或另拼精简格式（曾发生上报文本只拼摘要行且时间戳臆造，与实际轮次时间对不上）。

**示例**（content 含标记与换行，务必用单引号整体包裹，避免 shell 对换行/引号的转义破坏）：

```bash
# 盯盘上报
cli.py report.submit_summary watch '========== 盯盘总结 10:45:28 ==========

【持仓分析】当前空仓

# 复盘上报
cli.py report.submit_summary review '========== 复盘总结 2026-07-09 ==========
【当日盈亏】今日 +1104.76元(+0.7%)，累计 +58.35%；持仓：格科微+4.05%、华大九天+0.5%。
【情绪演变】大盘情绪 30→44，短线温度 30→70 偏激进，主力净额 -785→+269 亿反转。

[柚子 AI] 复盘 | 盈亏:+0.7% | 反思:加仓合规'
```

> - `log_type` 仅 `watch`（盯盘）/ `review`（复盘），与阶段一一对应
> - **失败隔离（硬约束）**：上报是本轮流程的**最后一步且完全旁路**。`report` 已保证上报请求 10s 超时（`_post` timeout）并吞掉**一切**异常返回错误信封（`code ≠ 200`）—— 上报在技术上不可能让本轮卡死、抛异常或中断
> - **收到任何上报结果一律忽略、不重试、不记错**：网络错 / 超时 / 服务 5xx / `code ≠ 200` 均视为"留痕失败、无所谓"，正常结束本轮；**绝不为上报重试**，**绝不因上报结果改变情绪 / 仓位 / 买卖任何决策**（上报只留痕、不参与判断）
> - 总结文本已输出给用户并写入本地 `data/`，上报失败 ≠ 本轮失败，更 ≠ 影响下次盯盘
> - `content` 为 `str` 类型注解，**不支持 `@文件` 引用**（cli 仅对 dict/list 参数展开 `@路径`）；多行文本务必用单引号整体包裹

## 附录 A：盯盘教训（经验教训）

> 本节是历史盯盘中沉淀的**经验教训**，是总纲通用纪律（§5.1 五条硬纪律）与心法纪律的**具象化案例**，供 agent 避免重蹈覆辙。后续是否增删由用户指示，agent 不得自动追加新案例。教训记录的是**发生当时**的规则状态，其中题材阶段 / 买点措辞（如"Day 1 买点 5 / Day 2 低吸 / Day 3+ 回踩"）为**历史快照**——判定一律以策略正文当前版本为准（§二 二元总纲、§2.3 状态机与量化要件），两者冲突时以正文为权威。

### A.1 教训一：误用"主锚"概念 → 仓位完全采用盘面分析，不自创名词

- **错误表现**：盯盘中 agent 写"大盘温度是主锚"作为不开仓的论据
- **根因**：禁止自创判定名词，但 agent 仍在论据中自创概念，违反输出纪律
- **正解**：仓位完全采用盘面 `final_analysis.position_limit`，**不**自创调档。情绪判定只引用盘面返回的 `sentiment_label` / `sentiment_capital_alignment` 两指标（§0.1）

### A.2 教训二：自拾额外指标 → 情绪判定只用盘面两个温度

- **错误表现**：盯盘记录中 agent 列出炸板率 33.3%、大面 57 家、昨日涨停破位 23.5% 等指标作为"情绪背离"的论据
- **根因**：心法明令"不自行统计炸板率、跌停数、连板高度"等指标，但 agent 在压力下仍自拾这些字段来"证明情绪差"
- **正解**：情绪判定**只**用盘面的两个温度 + alignment（总纲 §5.1 第 2 条）：
  - 大盘情绪温度：`temperature_score` + `temperature_label`（只用于 `position_limit`）
  - 短线情绪温度：`sentiment_label` + `sentiment_capital_alignment` 决定是否开新仓（§0.1 两指标）
  - 炸板率、大面家数、破位率、连板高度、涨跌停家数等**一律不准自拾**作为情绪论据

### A.3 教训三：复述 `position_reasoning` 区间 → 诱发自创调档

- **错误表现**：盯盘输出复述"盘面给出 65-80% 区间，本日取中下沿 65%"——**复述本身就在做"取档"动作**
- **根因**：把 `position_reasoning` 当作"可读"字段，但盘面分析在 reasoning 中写"区间+微调"是它的内部推理过程，agent 复述就会养成"区间"概念
- **正解**：`position_reasoning` 仅供日志/解释，**禁止**复述区间/上下沿/微上修/微下修等表述。盯盘输出**只**引用最终数字 `position_limit`（总纲 §5.6、§7）

### A.4 教训四：候选池为空就什么都不做

- **错误表现**：盯盘中 `get_strategy_trend_stocks(6)` 创业板强趋势过滤后无可买标的 → agent 直接输出"无候选"并**中断检查链**，跳过持仓止损止盈检查、跳过输出摘要
- **根因**：把"取候选池"误读为"全部操作"，忽略了下游的持仓检查
- **正解**：选股接口是**三池全拉合并**（6 + 10 + 7），三池全部不足才"无候选"；但即使"无候选"也要**继续执行**持仓止损止盈检查（§三）+ 输出摘要（§七）+ 盘面 `action_advice` 解读（§0.4）。**取候选池只是检查链的一个节点，不是全部**（§1.1、§五 checklist）

### A.5 教训五：把盘面个股名单当白名单 + 只看主池就停

- **错误表现**：盯盘中 agent 先只拉 `get_strategy_trend_stocks(6)` 创业板主池就停止分析（用户指出后才补拉 10/7）；并且把"是否落在 `final_analysis.attack_directions[].stocks[].code` 名单内"作为个股取舍与仓位分档依据（名单内单只≤30%、名单外≤20%）
- **根因（双重错误）**：
  1. **只看主池**：误读 §1.1「三池全拉」为"主池够数就停"，忽略了三个池覆盖的板块结构不同（创业板偏成长、主板偏周期/大市值），活跃方向核心标的可能落在任一池。主池充足≠视野完整
  2. **名单当门槛**：把盘面的 `attack_directions[].stocks` 当成"白名单"，忘了它只是盘面论证方向时引用的**样本**，受限于数据源，**有偏且不完整**。趋势股池里形态更优、买点更好但不在名单内的标的，被这个隐门槛挡掉了
- **正解**：
  1. **六池全拉合并**：`get_strategy_trend_stocks(6)` + `(10)` + `(7)`（趋势三池）+ `get_main_inflow_top`（主力净流入榜）+ `get_amount_top`（成交额榜）+ `get_hourly_hot_top`（小时热度榜）**全部拉取**，按 `stock_code` 合并去重为统一候选集，再做买点分析（§1.1）—— "全拉不偏废"的精神从三池延伸到六池
  2. **方向有用、名单不卡**：盘面的 `direction`（方向）有参考价值（聚焦视野），但其下 `stocks[].code` **不进选股池、不作个股取舍裁判、不作仓位分档依据**。买不买由趋势形态 + 买点 + 纪律**自主判定**（§0.2、§1.1，总纲 §5.1 第 3 条）
  3. **单只仓位统一 ≤30%**，具体多少由买点位置与追高风险自行研判，**不**按名单内 / 外、**也不**按来源池（趋势三池 vs 主力 / 成交额 / 热度榜）分档（§1.1）
  4. **新来源只扩大发现面、不降标准**：主力净流入榜 / 成交额榜 / 小时热度榜命中后必须补验趋势形态（`get_daily_k_data` + `get_stock_info`），不达标即剔除 —— 候选面变广，趋势形态这道门槛照常卡（§1.1）

### A.6 教训六：把撤退名单当白名单 + 方向逆转信号外推为机械动作

- **错误表现**：
  1. 盯盘 600487 亨通光电时，检查 `retreat_directions[].stocks[].code` 名单里没有 600487，输出"持仓不在撤退方向"——实际亨通光电主营光模块/CPO，属撤退方向 `CPO/光模块/AI硬件制造端` 板块归属范围
  2. 观察到 `vs_prev_analysis` 报告"CPO/光模块制造端撤退力度加大"，机械外推为"明日开盘第一时间减仓"——把盘中信号当作下一时点动作的预设承诺
- **根因**：
  1. **名单当白名单的延伸**：A.5 警告了"攻击方向名单当门槛"，本条扩展到"撤退方向名单当白名单"——任何盘面名单都是论证样本，不能作为个股归属的最终裁判
  2. **信号外推成动作**：把"观察到的状态变化"自动映射成"未来必须执行某动作"，忽略了"下一时点盘中要重新跑判定"的基本原则
- **正解**：
  1. **板块归属判定**：`get_stock_info(stock_code).hot_categories` + 主营业务描述 vs `retreat_directions[].direction` 字面匹配/同板块 → 视为该撤退方向（红线 0%）；名单只作交叉验证（§0.2 撤退方向识别、心法 §五）
  2. **信号 ≠ 动作**：`vs_prev_analysis` 报告方向变化是**待评估的盘中信号**，下一时点的具体动作（减仓 / 清仓 / 继续持有）由下一时点的盘中判定决定（§0.4 撤退/风险/操作表、总纲 §5.1 第 4 条）
  3. **输出只描述当下**：盯盘一行摘要只陈述当前事实 + 明日需重新评估的检查项清单，**禁止**承诺式动作预设（§7、总纲 §八）

### A.7 教训七：持仓只用快照价判定 → 加速止盈是形态信号，必须采集分时

- **错误表现**：盯盘 300083 创世纪时，只用 `get_positions`+`get_batch_stock_zdf` 的快照价 / 浮亏%（`zdf` +1.48%、浮亏 -1.87%）判定"未触发止损、时间止损通过、继续持有"，**未采集分时**。实际该股当日早盘冲高 +7.05% 后全天阴跌回落至 +1.26%，形成长上影 + 放量滞涨 + 与机器人板块集体走强（+82 亿、涨停 34 只）背离，明确构成 §0.6 加速止盈信号，被用户指出后才纠错卖出
- **根因（双重）**：
  1. **数据采集结构性失衡**：给候选股拉了分时认真看买点，给持仓股却只取快照——"重买入决策、轻持仓监控"。而加速止盈（长上影 / 放量滞涨 / 板块背离）只能从分时序列识别，快照价给不出形态
  2. **"伪正向"误判**：用"今日 `zdf` > 0 的收盘红盘"论证"预期上涨已现、时间止损通过"，掩盖了过程上的冲高派发——冲高回落在收盘 `zdf` 上看起来也是"涨"
- **正解**：
  1. **持仓分时与主力资金强制采集**：每轮持仓复核对每只**可卖持仓**（`available_volume > 0`；当日买入 T+1 不可卖的跳过，总纲 §3.3）调 `get_stock_minute_trendline`（涨跌 `y1` + 主力 `y2`）+ `get_stock_info`（板块归属），按 §0.6 判四信号（含资金背离），禁止只用快照价判加速止盈（总纲 §3.3、§5.1 第 5 条）
  2. **上涨质量判别**：时间止损的"预期上涨已现"必须是稳健上行 / 高位横盘；冲高回落（日内最高 − 收盘 ≥ 4%）不算，触发离场
  3. **板块背离即异常**：所属 `attack_directions` 当日集体走强、个股却冲高回落 / 逆势走弱 → 走势与板块背离，加速止盈（不依赖主观的"板块地位"判定）
  4. **优先保利润少格局**：非强势股出现异常默认倾向卖出，不死扛（心法 §4.5）

### A.8 教训八：买入只用 zdf 快照判定 → 分时未现卖点同样要采分时（A.7 的买入镜像）

- **错误表现**：盯盘 300604 长川科技时，以"主力 +2.24 亿 + 买点 4 低吸区 `zdf` +2.73% + 方向归属命中"买入，**未采分时**。实际该股主力大额进场却涨幅压在低位（钱进价不涨），属放量滞涨 / 派发嫌疑，买入后仅 9 分钟（10:49）即触发长上影 4.51% + 放量滞涨 + 板块背离加速止盈信号，因 T+1 锁定无法卖出
- **根因（双重）**：
  1. **买入与持仓的分时采集不对称**：持仓每轮强制采分时判四信号（教训 A.7 + §五 checklist 持仓分时采集项），买入候选却只查 `get_stock_info` / K线，第 5 条「分时未现卖点」流于形式——同一个放量滞涨形态，持仓认得出、买入认不出。A.7 补了"持仓不采分时"，漏了"买入不采分时"
  2. **主力净流入被当无条件加分项**：把"主力 +2.24 亿"当正向证据，忽略了"大额进场却只涨 2.73%"恰恰是资金-涨幅背离的派发信号；原有规则只有资金背离止盈（价涨资金出，§0.6），缺"资金-涨幅背离"的买入否决（资金进价滞涨）
- **正解**：
  1. **买入分时与主力资金强制采集（对称 A.7）**：买入候选必须调 `get_stock_minute_trendline`（涨跌 `y1` + 主力 `y2`）+ `get_stock_info`（板块归属）按 §0.6 判四信号，任一成立否决买入（§2.2 第 5 条硬前置、§五 checklist 买入候选分时采集项）
  2. **资金-涨幅背离即派发嫌疑**：主力大额净流入但涨幅与资金量级明显不匹配 → 优先怀疑派发而非低吸，分时确认（§2.2 第 6 条）
  3. **放量滞涨买卖对称**：铁律 7「放量滞涨就走」的判断同时适用于买入侧——分时已现放量滞涨 / 长上影的标的不买（心法 §4.5）
  4. **`zdf` 落在区间 ≠ 低吸成立**：买点 4 第 3 条的 -3%~+3% 是必要非充分条件，必须叠加第 5 条分时确认，禁用涨幅快照短路判定

### A.9 教训九：多日上涨后的日内回落 ≠ 低吸（追高风险）

- **错误表现**：标的连续上涨 3 日及以上（如 601899 紫金矿业 07-20~07-22 累计涨约 13%，603993 洛阳钼业同期累计涨约 12%），盘中从日内高点回落到 +1%~+3% 区间，agent 就按"买点 4 低吸"买入
- **根因（双重）**：
  1. 把"日内冲高回落"机械等同于"健康回踩"，忽略了多日趋势已充分演绎、短期获利盘丰厚的背景；此时日内回落更可能是早盘资金派发后的余温，而非新的承接
  2. 对 `y2` 主力资金序列"先入后出"形态（前段流入上行、后段持续回落，出货末端）的警示意义认识不足，仅因 `fund_divergence == "normal"` 未触发四信号就视为资金面健康，未与多日趋势衰竭结合判断
- **正解**：
  1. 在 §2.2 低吸买点中增加"趋势衰竭"前置过滤：近 3 日累计涨幅 ≥ 15% 或连续 3 日收阳，必须确认当前时点正处于当日深度回踩末端或刚企稳（曾跌破昨日收盘价 / MA5 且明显承接、当前涨幅未大幅反弹）才可买；若当前已大幅反弹则禁止买入
  2. `y2` 主力资金序列呈"先入后出"形态且近 3 日累计涨幅 ≥ 15% 时，直接否决买入
  3. 买入 reason 必须显式说明：近 3 日累计涨幅、是否处于回踩末端、为何判定为真承接而非追高末端
  4. `action_advice` 中出现"逢低吸纳 X"不等于 X 已出现买点，仍需独立技术校验

### A.10 教训十：题材阶段错配导致追涨杀跌

- **错误表现**：标的所属题材已反复活跃多日（如 601899 紫金矿业、603993 洛阳钼业所属有色金属 / 锂电池方向 07-20 以来已持续强势），个股本身也已连涨 3 日左右，agent 仍按"低吸"或"追涨"买入；买入后次日缺乏持续性，只能割肉离场，形成"追涨杀跌 + 次日割肉"循环
- **根因（三重）**：
  1. **未区分题材生命周期**：把 Day 3+ 持续发酵阶段的票套用 Day 1 追涨或 Day 2 低吸规则，没有按阶段匹配买点
  2. **量价持续性判断缺位**：买入时只关注方向命中、资金流入、当日涨幅落在区间，未确认是否出现"上涨缩量回踩"或"持续放量上攻"等健康量价信号，也未识别"放量滞涨 / 冲高回落 / 资金先流入后流出"等衰竭信号
  3. **对持续性的评估不足**：买入前没有回答"如果今天不买，明天是否还能涨"这个问题；题材末端、获利盘丰厚时，日内回落不是低吸，而是派发余温
- **正解**：
  1. 买入前必须按 §2.3 判定题材阶段：Day 1 首次爆发、Day 2 次日分歧、Day 3+ 持续发酵、其他 / 模糊 → 放弃
  2. Day 1 用买点 5（追涨，0% ~ 7%，持续放量上攻）；Day 2 用买点 4（水下低吸，-5% ~ +3%，缩量回踩）；Day 3+ 只参与严格健康回踩（-3% ~ +3%，量价健康），否则空仓
  3. 买入前必须按 §0.7 确认量价健康：上涨缩量回踩 / 持续放量上攻 / 量价齐升可买；放量滞涨 / 放量冲高回落 / 放量下跌 / 缩量阴跌 否决
  4. 买入前自问："这股明天还有资金愿意接力吗？"若拿不出量价证据，直接放弃，不勉强交易
  5. 买入 reason 必须写明：题材阶段、近 3 日累计涨幅、量价健康信号、为何判定仍有持续性

### A.11 教训十一：主力净流出 + 低换手仍买入 → 资金面硬条件是低吸的一票否决门槛（非套利专属）

- **错误表现**：盯盘 601789 宁波建工时，以"算力方向持续发酵健康回踩 + 日 K 在 20 日线上方多头排列 + 分时回踩至 -1.34% 后承接回升 + 主力资金无背离"为据，于 13:39 买入 9800 股（4.46 元，约 29.76% 仓位）。实际 `get_stock_info` 显示：主力净额 `amount_main` = **-135 万（净流出）**、换手率 `turn_z` = **3.92%（<5%）**——套利资金面双重红线全不达标。分时全程在水下（`y1` 最高仅 0%，从未涨过）、`fund_trend` = `flat`；买入理由引用的"回踩 -1.34% 后承接回升"是**早盘 10:06 低点 → 10:49 回到 0%** 的走势，到 13:39 买入时该回升早已结束，下午分时在 -0.45% 横盘偏弱。换手率轨迹：涨停次日 7/28 的 10.52% 逐级衰减至 8/5 的 3.92%，量价衰竭
- **根因（四重）**：
  1. **资金面硬条件在低吸买点未落地为前置否决**：§2.2 低吸的前置否决过滤（第 5/6/7/8 条）只卡分时四信号 / 趋势衰竭 / 题材阶段，缺"主力净流出即否决"这条最基础的硬门槛；§0.5 套利资金面验证只约束"套利标的"，龙头低吸被当作例外漏网
  2. **"无背离"偷换成"主力承接"**：买入理由写"主力资金无背离"，把 `fund_divergence == "normal"`（仅表示未出现"价涨资金出"的背离形态）当成"主力资金健康承接"，掩盖了 `amount_main` 实际为负（净流出）的事实——**normal ≠ 净流入**
  3. **"健康回踩"时间错位**：买入理由引用的回升走势发生在买入时点（13:39）**之前数小时**（早盘 10 点），到买入时分时已转为横盘偏弱；健康回踩必须是**买入时点的当下分时状态**，禁止引用当日早于买入时点已结束的历史走势
  4. **换手率衰减的量价衰竭未识别**：涨停后换手率从 10.52% 逐级萎缩到 3.92%，是题材资金撤退、活跃度下降的典型量价特征，却被当作"持续发酵"
- **正解**：
  1. **资金面硬否决前置（与套利 §0.5 统一，§2.2 第 9 条）**：买入前必须调 `get_stock_info` 取 `amount_main` / `turn_z`，主力净流出即一票否决，换手率 < 5% 同样否决，**不因龙头低吸豁免**
  2. **"无背离"≠"主力承接"**：`fund_divergence == "normal"` 只表示没有"价涨资金出"的背离，必须另外确认 `amount_main > 0` 才算资金承接；禁止用 normal 当买入加分项或掩盖净流出
  3. **健康回踩必须取买入时点的当下分时**：禁止引用当日早于买入时点已结束的回升走势作为买点依据；买入时点分时若已横盘偏弱 / 走弱，则回踩已失效
  4. **换手率趋势校验**：近 5 日换手率逐级衰减（如涨停后持续萎缩）属量价衰竭，结合 §0.7 否决买入
