## 试错执行纪律（资格日配额制）

> **动机**：试错仓的本质是用 5% 的有限亏损买信息（分笔建仓，买入手册 §2.4）。资格日反复空手 → 通道样本永远攒不够（审定条款长期停留在观察级）→ 仓位永远压在试错档 → 更没有动力出手——死循环；且"空手"在旧口径下是零成本选项（只惩罚错出、不惩罚空手），系统单调向保守漂移。配额制把"资格日出手"从选项变为纪律，"空手"须给出三选一合法理由，出手率与踏空纳入复盘计量（复盘手册 §7.4 执行计量）。

**资格日定义**：当日任一通道资格为真的交易日——`a_open` / `a2_open` / `b_open` / `c_open` / `d_open` / `ef_open`（云端节点派生，每轮现算；通道 G 已退役，其试探语义由 C 升温档承接）。

**执行义务**：资格日内，对应通道**当日认证通过**（该通道全部要件成立，如 A2 两件套 / D 连榜资格 / E 尾盘认证 / F 情绪双正向 + 三件套）**且**四层矩阵无硬否决（①②③层任一层拦截或④层红线命中）**且**六池存在合规标的 → 当日**必须**执行 ≥1 笔试错（单笔 ≥5%，买入手册 §2.5 试错仓下限）；下单未成交（涨停封板 / 流动性不足）在盯盘总结记录"已尝试 + 未成交原因"，视同履约。**同资格日多通道时按"当日一试错笔额度"合并计算**（冰点回暖日的 F / E 共享一笔，谁先成立谁执行）；**配额不降低任何选股标准**——禁止为凑配额买入不合格标的（A.4 教训照常生效：无合规标的不硬凑）。

**合法空手（三选一，须在盯盘总结记录具体原因，缺记录即视为执行缺失）**：

1. 通道当日认证未通过（记录差在哪条要件）
2. 四层矩阵硬否决（记录哪层哪条）
3. 六池筛选后无合规标的（记录筛选过程与结果——筛了什么、为什么全不合格）

**盘中预选（对策尾盘窗口瞬态）**：资格日从上午轮次起维护**预选名单**（六池筛 + 资金面硬条件（买入手册 §0.5）+ 买入侧分时分级（买入手册 §2.2 第 5 条）预检），写入盯盘总结候选分析板块逐轮更新；尾盘窗口通道（D / E）只做最终分时确认与下单，**不做从头选股**——25 分钟窗口内现选现判必然超时错失。

## 出手节奏与组合纪律（跨路径硬闸，与四层矩阵 AND 叠加、取最严）

> **动机**：单笔判定合规 ≠ 组合安全——衰竭画像股在日内拉升段买入，炸板风险在组合层被放大。四层矩阵管「单笔能不能买」，本节管「组合层的否决记忆与载体位置」。事实数据由机械层「纪律预算」注入（总纲 §3.1.2），agent 只消费注入数字，不自行翻台账 / 重算；注入失败时按退化流程自行取数（journal.read_decisions + trading.get_orders + 持仓快照）。**被本节否决的空手视同四层矩阵硬否决，按「试错执行纪律」合法空手第 2 条记录。**

1. **否决一致性**：当日已否决（veto）标的当日复买，必须**显式推翻原否决理由**（注入「当日否决记录」）——举证证据变化（如主力净额量级突变、方向地位升级），证据未变不得复买；无 veto 记录的标的不受此限。背景：agent 每轮独立上下文，写在总结里的否决下一轮看不见，台账是否决记忆的唯一载体
2. **衰竭画像跨路径硬否决**：命中买入手册 §2.2 第 7 条衰竭画像口径（近 3 日累计 ≥ 15% / 近 5 日累计 ≥ 25% / 近 5 日内有 ≥ 30% 急涨段且回调未触 MA5 / 连 3 日收阳）的标的，**任何通道**的新开仓只允许「当日深度回踩末端或刚企稳」的低吸形态（同 §2.2 第 7 条承接要件）；**日内拉升段（当前 zdf > +3% 或已从日内低点反弹 > 2%）禁止以其为新买入载体**——方向一致加速日的封板 / 拉升对高位股是最后体力，分歧时第一个炸。已持仓不受影响（走个股级止盈止损纪律）
3. **发酵晚段买点约束（height + 涨停家数 + 连强天数，三条件 AND，缺一不可）**：**height ≥ 4 且 板块当日涨停 ≥ 12 只 且 连强 ≥ 3 日（含当日，三日均居 zt_count 榜前 3）** → 该方向新开仓**禁买点 3 突破追买，仅保留买点 4 深度回踩低吸**（承接要件同衰竭画像条口径：买入手册 §2.2 第 7 条承接要件）；该方向持仓的止盈评估按 §3.1「优先保住利润，非强势股少格局」从宽执行——加速止盈信号苗头即倾向落袋，不死扛等新高。依据：涨停家数爆发 + 高度打出 + 连强多日 = 一致加速高潮段，次日大概率分歧，跟风 / 中军分歈权最先挨打，追突破是买在人声鼎沸处。数据 = 注入「板块热度前 3」的 `zt_count` / `height` + 历史热度榜直查（历史日用 `get_top_hot_spots --date <日期> --limit 3`，当日行盘中为空、当日一律用 `get_hot_spot_list --sort_by zt_count` 实时榜，连榜口径同通道 D 判定）。**首板潮保护（明文豁免，防误伤主线确认日）**：涨停家数再多（15~19 只亦然），height < 4 或连强 < 3 日 → **不判晚段、不禁资格**——涨停潮 + 低连板高度 = 首板潮，可能是主升确认日。**禁止自创定性**：单一 height 或单一涨停家数不得自创「方向高潮 / 退潮」定性；晚段判定只允许由本条三条件组合成立，禁止增删条件或改阈值；方向是否终结仍由 §3.0 D 条（连强终结）与撤退红线判定
4. **落账纪律（买入流程硬步骤）**：买入成交后立即调 `cli.ts journal.record_decision --action buy`（含方向归属 direction、成交价量、一句话理由）；否决候选后立即调 `--action veto`（含否决理由——复买核对依据，写清关键证据）。机械层每轮对账补录漏记笔（source="orders"，方向待确认）——agent 主动落账是首选路径，机械层补录只是兜底；发现「方向待确认」的补录笔，下次出手判定前先补正方向归属
5. **已买标的复买视同补足笔（跨轮 / 跨日统一口径）**：已买入标的（当日或历史持仓）再次进入出手判定时，一律按买入手册 §2.4 分笔建仓的**补足笔**处理——仅当强确认出现（放量突破前高 / 整理平台、分时回踩不破均价线快速拉起 + 主力持续流入、持续放量上攻 / 量价齐升延续，完整要件以 §2.4 为准）才可再出手，买入 reason 必须对照首笔台账买入记录（方向 / channel / 理由）写明"本次确认了什么"；无强确认 → 不出手，**不得当作独立新买点重复出手**（防日内反复小额追加推高 T+1 不可卖暴露）。补足仍视同新开仓过层①，额度受单只红线扣减现有市值后的差额约束；"确认不现禁止摊低成本式加仓"（§2.4）照常生效。pipeline 侧由池行「持仓」标记 + 终选 / 核验 / 终裁会话按本条与 §2.4 执行

## 核心原则（一行版）

**选股用今日趋势池 + 今日异动拉升池 + 近期异动上涨池 + 主力净流入榜 + 成交额榜 + 小时热度榜六池合并（筛选标准一致、形态这道门槛照常卡）；开仓资格过四层矩阵（市场层状态机 × 当日层 LLM 两指标 × 账户层 position_limit × 个体层心法红线，见「状态机索引」）；仓位、情绪取盘面分析原值不调档；个体纪律用心法卡，操作细节按本文件与买入手册（买入细则按需读取，见文件头路由表）。**

### 0.1 仓位采用与开仓触发

> **角色定位**：本节开仓触发部分是四层开仓裁决矩阵（「市场节点索引」）的**当日层（②）**，与市场层云端节点 AND 叠加——节点给资格后，本节两指标再判当日盘面是否恶化到禁开仓；仓位部分是矩阵的**账户层（③）**。

**仓位（直接采用，不自行调档）**

- **唯一字段**：`final_analysis.position_limit`
- **直接采用**作为本轮**新增可动用**仓位上限，**不主动降、不主动加**；`position_limit` 只约束"是否还能开新仓"，**已有持仓不因 `position_limit` 降低而被强卖**（持仓去留归 §三 止盈止损 + §0.2 撤退方向判定，**不**因仓位低而强卖进攻方向持仓）；**极端值明示（A.12 教训）：`position_limit=0` 的语义是"禁开新仓"，不是"总仓位目标为 0"——limit 连续压到 0 也不触发任何清仓 / 加速减仓，防守阶段同样不构成任何卖出依据（阶段只管开仓），唯一合法卖出依据仍是 §3.0 环境信号 + 个股信号（四信号 / 止损 / 撤退红线）+ 分批纪律**
- 个体持仓上限（心法 §五：单只 ≤ 30%、同方向 ≤ 50%）**同时**生效
- 整轮流程：先读 `final_analysis.market_overview`（必读）→ 再读 `position_limit` → 用 `position_limit / 100` 作为总仓位上限
- **禁止**：不复述 `position_reasoning` 区间 / 上下沿 / 微调；不基于 `sentiment_label` 调档；不基于"主锚 / 权重 / 核心信号"调档

**开仓触发（两指标联合判定）**

**唯一判定**：是否开新仓由 `sentiment_label` + `sentiment_capital_alignment` 两者联合判定。

> 与心法 §三 仓位哲学的关系：心法四象限（短线差大盘差→禁止）与本节 `alignment=双弱→禁` 是**同一判定的两种表述** —— `sentiment_capital_alignment` 是盘面分析把大盘分值三档 × 短线两档综合后的落地信号（双强 / 普涨 / 胶着 / 逆势 / 双弱五词）。心法哲学是底层依据，本节是可执行判定，不另立第四条件。

**禁开仓条件（两者同时满足）**：

| 字段 | 条件 |
|------|------|
| `sentiment_analysis.sentiment_label` | ∈ {`偏保守`, `保守`} |
| `final_analysis.sentiment_capital_alignment` | == `双弱` |

- 两者同时满足 → **停止开新仓**（禁开仓只作用于"新仓"，**不等于**清掉已有持仓；已有持仓去留归 §三 止盈止损（含 §3.0 环境分层减仓）+ §0.2 撤退方向判定）；**豁免：冰点链内的先手通道（A / A2 / B / D）不检查两指标——冰点链 = 当帧 ∈ {冰点, 连续冰点}（`a2_open` / `b_open` / `a_open` 任一为真）。依据：①无共振方向（A / B）时两指标必然触发，属冰点常态；②共振节点（A2）初帧大盘往往仍冰、两指标同样触发——题材资金先动手、指数后跟上，先手买在大盘变好之前，非恶化——假拉起过滤由 A2 两件套承担（板块涨停居前 3 + 风向标集体上攻是资金真实回流的硬证据，强于 alignment 定性）；顺周期熔断不卡逆周期先手，风控由通道自身要件承担（两件套 / 贯穿性主线 + 已回调、试错档仓位、T+2 验证离场）。升温链的 C / D 照常检查（升温进程中恶化属异常熔断）。账户层不在此豁免内：`position_limit` 硬约束照常生效，limit=0 时冰点先手亦不出手（LLM 极端悲观熔断保留一道）**
- 任一不满足 → 仍可按 `position_limit` 执行
- **alignment 的卖出侧含义**：`alignment == 双弱` 未叠加保守情绪时不禁开仓，但已构成持仓侧 §3.0 环境分层减仓的触发条件（开仓与减仓两个维度各自生效，不互相豁免；**例外——冰点链期间的先手试错仓不因环境级 alignment=双弱 触发减仓，见 §3.0 环境级触发行的豁免限定**）

> 短线交易每天都会有新题材和持续发酵的方向，情绪温度回答"当前是否适合开新仓、能上多少仓"。具体做哪个题材、位置高低是否接盘，参照盘面分析的题材分析（`hot_rotation_analysis`）字段 + 选股买点纪律各自把关，**不**用一个全局风险等级去一概而论地否定开仓。

**判定原则**：
- 只用 `sentiment_label` + `sentiment_capital_alignment` 两指标，不自创五词之外的标签（五词 = 双强 / 普涨 / 胶着 / 逆势 / 双弱）
- `sentiment_label` 单独**不**禁开仓 —— 只有同时叠加 `alignment=双弱` 才禁
- 大盘温度（`temperature_score` / `temperature_label`）**不**作开仓过滤器

### 0.2 活跃方向判定（盘面进攻 / 观察名单整体只是举例，不作门槛、不作优先级、不构成买入依据）

**活跃方向** = 近期反复活跃、持续发酵的热点题材。盘面返回的相关字段（仅作盘面描述的参考来源，**不构成选股门槛或买入依据**）：
- `final_analysis.attack_directions[].direction`（盘面分析二次筛选后的进攻方向）
- 顶层 `data["attack_directions"]`（次要参考）
- `hot_rotation_analysis.attack_sectors[].sector`（题材分析识别的进攻方向）
- `final_analysis.observe_directions[]`（未达门槛的观察方向，苗头待确认）
- `hot_rotation_analysis.emerging_sectors[]`（新冒头方向）

> **方向 vs 个股名单的辨证（核心认知）**：
> - **方向名（`direction` 字段，如"光通信 / 光纤"）与名单里的个股（`stocks[].code`）都是盘面描述的举例**——只描述"现在盘面在讲什么"，不构成选股门槛、不是优先级、不是买入依据
> - 个股名单受限于盘面喂给它的数据源（成交额榜 / 资金流榜等），**有偏且不完整**；趋势股池里完全可能有形态更优、买点更好、但名单没列出来的标的
> - 盘面方向结论中**唯一被消费为硬规则**的是"已撤退方向"（见下行 §0.2 撤退方向识别 + §4.1 心法红线）；进攻 / 观察名单硬消费 = 无
> - **结论**：买不买某只股、买哪个方向，由盘面数据（板块涨停居前、风向标集体上攻）+ 选股池（六池）+ 趋势形态 + 买点 + 纪律**自主分析**决定。盘面名单只用于"同方向持仓判定（50% 红线）辅助"和"日志/盘面描述"

**方向强度验证（不依赖盘面名单，由盘面数据直查说话）**：
- 板块当日实时涨停数 ≥2 且居全市场前 3（`get_hot_spot_daily_stats` 当日行 / `get_hot_spot_list --sort_by zt_count --limit 3`）
- 板块风向标（`attack_sectors[].key_stocks`，服务端查表填充）中 ≥2 只当日 `zdf > 3%`（集体上攻）
- **属性标签不作方向主源**：业绩线 / 并购重组这类"为什么涨"的说明性标签，是跨题材的交集标签，**不能**作为方向判定的独立命中（不满足"强度验证"的方向主源）——其涨停数与风向标是多个产业题材的拼盘，不代表一条独立主线。属性标签只作同方向选股的加分项（已带业绩预增 / 重组预期的个股在同题材内优先）

活跃方向 / 观察方向的作用范围（**只做这两件事，不做其它**）：
1. **同方向持仓判定** —— 用于心法 §五（同方向 ≤ 50% 红线，板块归属为准）
2. **日志 / 盘面描述** —— 摘要行"活跃 = attack[0].direction" 字段展示；不复述为决策依据

**不**作选股硬门槛；**不**作方向优先级；**不**因"方向进了攻击名单"而优先买或只买名单内个股；观察方向（`observe_directions` / `emerging_sectors`）按 §0.4 当日只记录、升级进进攻侧才买（苗头当日不参与）——苗头阶段的"方向地位"低于已确认的进攻方向，宁可错过第一波、不预判抄底。

**已确认方向（进攻侧）何时出手**：方向同时满足——① 强度验证通过（涨停居前 3 + 风向标集体上攻）；② 不在撤退名单（同帧冲突按撤退禁，标签不摘 = 不可出手）；③ 六池内该方向有合规个股（不涨停、close>MA5、资金面硬条件、分时四信号不否决、心法红线全过）——三项齐了才出手，缺一项空仓等。**不出手 = 合法操作**（§四 全局风控）——指三项未齐 / 矩阵硬否决 / 无合规标的时的空手；**条件全齐仍空手按「试错执行纪律」记执行缺失**（资格日配额制）。

**撤退方向识别**（必须保留，盘面方向结论中**唯一**被硬消费为规则的项）：

盘面分析的 `retreat_directions[].stocks[].code` 只是论证撤退方向时引用的**样本个股**，受限于数据源，**有偏且不完整**。名单漏列不代表脱离撤退方向，名单不卡 —— **判定依据是板块归属 + 主营细分**。

- 调 `cli.ts market.get_stock_info <code>` 取 `hot_categories`（热点分类列表）+ `up_reason`（涨停原因 / 主营业务描述）
- 持仓股 `code` ∈ 任意 `final_analysis.retreat_directions[].code`，**或**持仓股 `hot_categories` 中**任一分类**与某 `retreat_directions[].direction` 字面匹配或同板块 → 已撤退方向（红线 0%，清仓；执行时点按 §3.0 执行纪律第 2 条观察窗）
- **同帧攻击 / 撤退冲突的强制裁决**：当某方向在**当帧**既出现在 `attack_directions`（或 `attack_sectors`，如 `PCB/AI硬件`）又出现在 `retreat_directions`（如 `AI硬件（主题级）`），属于"板块内部大票出货、小票反抽的分裂"——**一律按撤退处理禁买**（不因涨停数居前 1、当帧主力净流入等回流量价证据而豁免），等盘面 LLM 把它从撤退名单移除的那一帧起才重新按进攻方向正常评估。**撤退标签不摘 = 不可出手，宁可惜过、不接飞刀**
- **同板块内细分方向（应用端 vs 制造端）**：当 `retreat_directions[].direction` 与 `attack_directions[].direction` 共享**同一板块名词**（典型：`CPO/光模块` 既可能出现在撤退方向、也可能以"光通信应用端"形式出现在进攻方向），必须用 `up_reason` 关键字二次细分：
  - **撤退方向细分关键字**（"制造端"特征）：`光模块` / `CPO` / `PCB` / `液冷` / `服务器机柜` / `封装` / `芯片制造` / `800G/1.6T 高速光器件` 等
  - **进攻方向细分关键字**（"应用端"特征）：`光纤` / `光缆` / `光棒` / `光器件应用` / `光通信运营` / `算力租赁` / `AI 应用` 等
  - `up_reason` 含撤退方向关键字 → 已撤退方向（红线 0%）；含进攻方向关键字 → **不**视为撤退方向（属活跃方向）
- 名单（`stocks[].code`）只作交叉验证参考，名单漏列不代表脱离撤退方向

**判定流程优先级**（不能省略任一步骤）：

1. **盘面直接列出的撤退个股**（`final_analysis.retreat_directions[].stocks[].code`）→ 直接判定为撤退方向，**优先剔除**。名单漏列不代表脱离撤退方向，但**名单列出的更应优先剔除**
2. **hot_categories 标签驱动**：仅当 `hot_categories` 包含盘面 `retreat_directions[].direction` 字面词汇（如 `大金融/证券/保险/银行` 或 `光通信/CPO/光模块`）时，才进入下一步细分。**不能因为某股 hot 包含多个标签就只看第一个**
3. **up_reason 二次细分**（仅当步骤 2 命中）：用主营描述判定撤退方向细分关键字 vs 进攻方向细分关键字，**主营细分占优**才判定为撤退
4. **未命中任何判定** → 不视为撤退方向（即使盘面 `attack_directions` 包含相似板块名词）

**常见错误**：
- ❌ 一只股 hot 为 `['CPO', '光通信', 'AI硬件']` → "含 CPO" 直接判撤退。**正解**：进入步骤 3，用 `up_reason` 细分主营是制造端（CPO/光模块）还是应用端（光纤/算力租赁）
- ❌ 一只股 hot 为 `['PCB', 'AI硬件', '业绩线']` → "PCB 在光通信撤退关键词里" 直接判撤退。**正解**：PCB 不在盘面 `retreat_directions[].direction` 字面词汇中（除非盘面明确将 PCB 列入撤退），不应自动判撤退

**同方向持仓判定**（心法 §五 仓位红线前提，仅用于 50% 红线，不用于个股取舍）：
- 持仓股 `code` ∈ 任意 `final_analysis.attack_directions[].stocks[].code`，**或**持仓股所属板块与某活跃 `direction` 同板块 → 视为同方向（上限 50%）。名单只是判定辅助，名单漏列不代表不同方向（板块归属为准）
- 持仓股 `code` ∈ 任意 `final_analysis.retreat_directions[].code` → 已撤退方向（红线 0%）

### 0.4 撤退、风险、操作（直接采用盘面结论）

| 盘面字段 | 含义 | 策略动作 |
|----------|------|----------|
| `final_analysis.retreat_directions[]` / `.direction` | 盘面判撤退的方向 | **硬红线一票否决**：该方向个股一支不买（无论当帧涨停多少、主力净流入多少、是否在 attack 名单中位居前列）；同帧又攻又撤按撤退处理禁买；持仓同方向纳入减仓（红线 0%）；标签不摘就一直不买 |
| `final_analysis.risk_warnings[]` | 风险提示 | 出现任一即纳入决策参考（不单独禁开仓） |
| `final_analysis.action_advice` | 操作建议 | **必读但需独立校验** —— LLM 对盘面的理解性提示，agent 应优先关注其指出的方向/风险；但具体买卖必须再经买入手册 §二 买点规则、§三 止损止盈、§0.2 撤退方向判定、§1.1 六池合并选股独立验证。出现"逢低吸纳 X""重仓 Y"等字样时，**不**等于 X/Y 已自动出现买点，禁止跳过技术规则直接执行。 |
| `final_analysis.vs_prev_analysis` | 与上次对比 | 持仓所属方向走弱 / 降级 / 逆转 → **当轮即启动 §3.0 环境分层减仓**（首笔逢高当轮执行，分批节奏见 §3.0；走势健康的通道试错仓豁免，见 §3.0「试错仓环境层豁免」统一条款）；每笔减仓的具体时机由当轮盘中分时判定，**禁止外推为"明日开盘第一时间 X"的跨日预承诺**（总纲 §5.1 第 4 条） |
| `sentiment_analysis.key_signals[看空+强]` | 加重风险信号 | 与 `risk_warnings` 一起纳入决策（总纲 §3.2 key_signals 分级） |
| `hot_rotation_analysis.retreat_sectors[].risk_level == "可能蔓延"` | 撤退风险分级 | **只回避该撤退方向**（不买其个股、持仓减仓）；**不封杀进攻方向开仓**，开仓资格仍归 §0.1（总纲 §5.5）（**仅当整段不为 None 时生效**） |
| `hot_rotation_analysis.retreat_sectors[]` | 资金撤退方向 | 同方向持仓纳入减仓候选；新仓回避该方向个股 |
| `final_analysis.observe_directions[]` | 未达门槛的观察方向（苗头） | **苗头待确认**：无当日资金量化证据，盘中不自动买卖（不计入撤退判定、不触发减仓、不进选股、不当撤退回避）；**复盘纳入当日方向事实记录（连续强势天数滚动累计）**，其后续是否升级由后续交易日盘中盘面重新判定 |
| `hot_rotation_analysis.emerging_sectors[]` | 新冒头方向（最多 2 个） | **通道 D 前瞻观察输入**：新冒头方向当日只记录观察（板块名 + 当日榜排名），次日若仍居市场前三即获通道 D 资格（`40` §二C 尾盘先手）；当日不因 emerging 双确认直接买入。不当撤退回避 |

### 0.6 加速止盈分时形态判定（分时字段）

加速止盈是**形态信号**，只能从分时序列 + 主力净额识别，**禁止用持仓快照的涨跌幅 / 浮亏% 代替**（给不出形态，见总纲 §3.3 与 §5.1 第 5 条）。对每只**可卖持仓**（`available_volume > 0`；当日买入 T+1 不可卖的盘中跳过一切卖出导向分析，见总纲 §3.3）消费机械层「持仓复核数据」注入的分时（`labels` + `y1.data` 涨跌全序列）、主力净额（`y2.data` 仅 1 个当日快照值，亿）与板块归属（`hot_categories` / `up_reason`），缺位才自调（总纲 §3.3）。**死字段唯一声明（其余文档不再重复）**：主力分时序列已下线——`fund_trend` / `fund_divergence` 恒为 null，资金背离信号停用、按总纲 §5.2 缺位跳过；主力净额现值看 `y2.data` 快照单值与 `get_stock_info` 的 `amount_main`，为负即资金不承接——买入候选侧即使净额为正，也须结合多日趋势位置与当日成交量综合判断，不可仅凭"主力净流入为正"就视为资金承接。按下表判四信号：

| 信号 | 判定 |
|------|------|
| 放量滞涨 | 冲高回落 / 不创新高 **且** 当日成交量（成交额）未较近期明显萎缩；因分时接口无分钟级成交量，"量能"以当日累计 `volume` / `amount` 相对近 5 日全天均量、按本节末「盘中实时量能的时段折算」口径折算后判定（未折算直接比全天均量 = 午前必判"萎缩"，禁止） |
| 长上影线 | 日内最高涨幅 − 当帧涨幅 **≥ 4%** |
| 走势与板块背离 | 所属 `attack_directions` 当日集体走强，个股却冲高回落 / 逆势走弱 |
| 资金背离 | **已停用**（依赖已下线的主力分时序列，`fund_divergence` 恒 null）——不构成触发，按缺位跳过（见本节开头死字段声明） |

**执行档位按方向归属分级（进攻方向宽、其余严；2026-11-05 用户审定修订——进攻方向持仓给更宽裕的观察时间，明确信号才清仓）**：

- **明确信号 → 清仓**（适用全部持仓，任一成立即全额执行）：
  1. **明确放量滞涨**：放量滞涨判定成立 **且** 距日内最高点已 ≥ 15 分钟（时效要件，初始校准值对齐 §3.1 开盘确认窗——给冲高后的走势留足兑现 / 修复时间，早盘瞬时冲高回落不构成明确，创日内新高则时效重新起算）；
  2. **明确长上影线**：日内最高涨幅 − 当帧涨幅 ≥ 4% **且** 距日内最高点已 ≥ 15 分钟（同一时效要件，防早盘瞬时回踩误判）；
  3. **主力由承接转流出**：当日累计主力净额快照（`y2` 末值 / `amount_main`）转负——非已停用的分时资金序列，用的是本节开头声明的活字段快照；买入时点净额为正是买入硬前提（买入手册 §0.5），当帧转负即"流入转流出"，资金事实优先于形态、**无需时效确认**；
  4. **多信号共振**：两项及以上信号同轮同时成立。
- **进攻方向持仓**（板块归属命中当帧进攻方向名单且未进撤退名单）：单一信号首现但未达明确（早盘未满 15 分钟时效 / 仅单项形态成立）→ **大幅减仓半仓，不清仓**；剩余半仓逐轮复评，升级为明确信号、或方向进撤退名单（§3.0 红线）、或触发个股级止损止盈时再全额执行；
- **其余持仓**（方向不在进攻名单 / 方向缺位）：任一信号成立即加速止盈清仓（原口径——方向无加成时不降档）；
- **默认态度不变**：出现任一异常默认倾向卖出、需明确理由才留（心法 §4.5 六条心得"优先保住利润"）。

**盘中实时量能的时段折算（换手 / 成交额与全天口径阈值比较时统一适用，原 §0.5 条款、买卖两侧共用）**：`turn_z` 换手率与当日累计成交额是**盘中累计值**，与全天口径阈值（换手 5% 线、近 5 日全天均量）直接比较会在午前系统性误判"不足 / 萎缩"——比较前按当日时间进度折算：**10:30 前按全天阈值的 50%、14:00 前按 90%、14:00 后按 100%**（例：10:15 判换手是否达 5% 线 → 用 2.5% 比；判成交是否缩量 → 与近 5 日全天均量 × 50% 比）。统一适用于本节放量滞涨量能判据与买入手册 §2.2 第 9 条换手线。

## 三、止盈止损（环境 → 方向 → 个股三层）

### 3.0 环境分层减仓（第一、二道防线：不等个股回撤才卖）

> **动机**：只看个股回撤信号（四信号 / 利润回撤 / 破位）卖出，是在"价格已经回落"之后滞后离场。题材整体回撤 + 大盘转弱时，**环境走弱先于个股走弱**——个股补跌在即，卖点必须前移到环境层，逢高分批兑现，不等个股回撤触发。

**触发矩阵（全部取盘面字段原值，不自创标签）**：

| 层级 | 触发条件（字段原值） | 动作 |
|------|---------------------|------|
| **环境级** | `final_analysis.sentiment_capital_alignment == "双弱"` | **全部持仓**：停止加仓，逢高分批减仓（首笔约 1/3，2~3 笔完成）。**豁免两类**：① 冰点链期间的先手试错仓（`channel=A/A2/B/D` 标注）无条件豁免——冰点期 alignment=双弱 是常态而非恶化信号（与 §0.1 开仓侧豁免同源，同一信号不得开仓侧判噪声、持仓侧反作触发器）；其退出走个股级（固定止损 / 技术止损 / 时间止损 / 四信号）+ 方向级撤退红线 + T+2 验证不成离场（`10` §五）。冰点链 = 当帧节点 ∈ {冰点, 连续冰点}；② 走势健康的通道试错仓豁免（下方「试错仓环境层豁免」统一条款）。**节点走出冰点（冰点回暖起）后 alignment 仍双弱 = 真恶化，标准仓照常触发** |
| **环境级** | `alignment ∈ {普涨, 胶着, 逆势}`（非双强非双弱的中间三词） **且** `vs_prev_analysis` 报告持仓所属方向走弱 / 降级 / 逆转 | **该方向持仓**：逢高分批减 1/3 ~ 1/2。走势健康的通道试错仓豁免（下方「试错仓环境层豁免」统一条款） |
| **方向级** | 持仓板块进入 `retreat_directions` / `retreat_sectors`（§0.2 板块归属判定） | 红线 0%，清仓（最高优先级；执行时遇刚翻红 / 加速拉升段可给观察窗，见执行纪律第 2 条） |
| **方向级** | 持仓所属方向从 `attack_directions` 名单消失（`vs_prev_analysis` 报告降级） | 同"中间档 + 方向走弱"行，纳入分批减仓。走势健康的通道试错仓豁免（下方「试错仓环境层豁免」统一条款） |

**试错仓环境层豁免（统一条款）**：

> **动机**：通道试错仓敞口已封顶（单只 ≤5%，试错档），环境层减仓的风控收益甚微（首笔 1/3 仅收回约 1.7% 敞口）；其职能是用小仓买通道假设的**完整验证信息**（T+2 验证 / 收盘 s 序列 / 次日资格），半路因环境 / 大盘层信号减仓会让验证信息不完整。环境 / 大盘层信号不作用于走势健康的试错仓；退出统一走个股级信号 + 方向级撤退红线 + 通道专属验证条款。

- **适用对象**：以 `channel=A/A2/B/C/D/E/F` 标注的先手试错仓，且**仍处试错档**（未按买入手册 §2.4 补足升级为标准仓——补足后敞口抬升，环境层减仓的风控意义恢复，豁免自动失效）
- **豁免条件（走势健康，当轮判定）**：个股加速止盈四信号（§0.6）全部不成立 **且** 固定 / 技术 / 趋势 / 利润保护止损均未触发——两者本就是每轮持仓复核必判项，零新增判定成本；任一成立 = 走势走坏，当轮即恢复环境层减仓义务（按触发矩阵逢高执行），个股级动作本身也照常执行
- **豁免范围**：环境级 alignment 两行（含 `alignment=双弱` 非冰点链场景）+ 方向级"从 attack 名单消失"行 + 节点先手减仓 A / B / C 三条（环境 / 大盘层触发）
- **不豁免（照常生效）**：方向级撤退红线（进 `retreat_directions` / `retreat_sectors` → 红线 0% 清仓）、节点先手 D（[板块]连强终结——方向层兑现信号，正是通道方向验证失败的标志）、个股级全部止损止盈（含目标止盈 / 时间止损）、通道专属验证离场（E·F 的收盘确认失败次日离场 / T+2 验证不成离场等）
- 冰点链期间的 A/A2/B/D 试错仓维持**无条件**豁免（不看走势——冰点期个股普遍承压，加走势条件反而收紧原豁免；噪声论据不变）

**执行纪律**：

1. **分批逢高，不恐慌一键清仓**：触发当轮执行首笔（约 1/3），其后利用反弹 / 分时相对高位分笔再减，2~3 笔完成——减仓也要卖在相对高位，禁止追着跌卖
2. **红线优先**：减仓途中命中撤退方向红线（0%）或个股固定止损（-5%）→ 剩余仓位不再等高位，两类执行时点纪律不同：
   - **撤退红线清仓的拉升观察窗**：撤退红线清仓执行时，若该持仓分时**刚翻红**（水下运行后刚上 0 轴）或**正处加速拉升段**（单边上行未现滞涨）→ 当轮暂缓卖出、开启观察窗等加速段兑现后再执行。窗口时长分层，**基础 5~10 分钟**（盯盘 5 分钟一轮 = 至多跨 2 轮，起点 = 触发轮调度时间），命中下列**观察余量加分项**逐级延长：
     - **板块龙头身份**：该股为所属撤退板块的强势龙头（近 5 日板块内累计涨幅居前 / 曾登板 / `up_reason` 或板块风向标名单标注龙头身份——龙头辨识度与带动性的代理指标）→ 窗口上限**延至 20 分钟**。依据：龙头先于板块异动、具有带动性，逆势拉升更可能是板块回流的先导而非出货
     - **主力资金非持续流出**：当轮主力净额快照（分时 `y2` 末值）≥ 0 → 窗口上限**再延 10 分钟**；当轮净额转负 = 资金转弱 → 取消本项延长、窗口上限**回落一档**（叠加 30 分钟回落至 20 分钟，单命中本项回落至基础 5~10 分钟），取消当轮已超回落后的上限 → 当轮执行。本项**每轮以当轮快照独立重估**（跨轮环比无数据源，盘中轮禁读 `watch-summary`，总纲 §十一）
     - 两项叠加最长 **30 分钟封顶**（盯盘 6 轮）
     - 窗口内**回落翻绿（分时末值 < 0）→ 立即执行**；**冲高滞涨（量化判定）→ 立即执行**：自窗口内日内高点回落 ≥ 2 个百分点**且**最近 3 分钟未创日内新高——回踩幅度 < 2 个百分点、或回踩后再度创新高，均属拉升后的正常换手回踩，**继续观察不触发执行**；封顶到点 → 无条件执行，**唯一例外：封顶轮分时末值恰为日内新高（主升段仍在延续）→ 顺延至不再创新高的轮次执行，顺延累计 ≤ 10 分钟，40 分钟为绝对极限**；窗口内当帧 LLM 将该方向移出撤退名单 / 重新列入 attack → 清仓义务解除、按常规持仓管理（龙头带动板块回流的兑现路径，以新帧字段为准）。个股逆撤退板块走强**不构成** §0.6「走势与板块背离」（该背离定义 = attack 方向集体走强 + 个股逆势走弱，方向相反），观察窗期间不得据此提前执行。观察窗只优化卖出时点，**不豁免清仓义务、不设第二次窗口**
   - **个股固定止损（-5%）无观察窗**：保命线不等形态，触发即卖
3. **与 §0.1 的边界**：`position_limit` 单独降低**不**触发本节减仓（"不因 limit 降低强卖进攻方向持仓"继续有效）；本节触发源仅限 alignment / vs_prev / 撤退名单三类字段
4. **不以偏概全**（总纲 §5.5）：非持仓方向的撤退 / 风险提示不触发本节；环境级触发（alignment=双弱）作用于全部持仓的仓位态度，方向级触发只作用于该方向持仓
5. 卖出 reason 必须写明触发字段原值（如 `alignment=双弱`、`vs_prev 报告 XX 方向降级`），与个股级 reason（§3.1）区分
6. **T+1 边界**：当日买入（`available_volume == 0`）的持仓当日无法执行减仓 / 清仓，不对其做盘中卖出导向分析（总纲 §3.3）；次日可卖后按当次盘面重新判定，**不预承诺**（总纲 §5.1 第 4 条）

**节点先手减仓（跨战法通用；各条证据分级不同）**：

> **动机**：本节触发字段（alignment / vs_prev / 撤退名单）是 LLM 对环境的**定性**判断，往往在回落已经发生后才翻转；先手减仓用可提前观测的**节点**信号在阶段转折确认前主动降仓，不等大幅回落才割肉。

| 节点 | 触发条件（盘中 / 晨起可判定） | 动作 | 证据分级 |
|------|------------------------------|------|----------|
| **A. 节点转弱晨起先手** | 晨起云端节点较昨日定格节点**转弱**（高潮 / 连续高潮 → 高潮降温 / 降温，连续升温 → 降温，任意 → 冰点 / 连续冰点） | 当日浮盈可卖持仓逢高分批先手减仓（首笔约 1/3，对齐本节执行纪律），不等个股形态走坏 | **数据支撑**：节点链由云端收盘序列幂等回放（代码权威、无本地阈值），节点确认后次日晨起相对个股形态确认是左侧先手 |
| **B. 温度回落当帧先手** | 当帧大盘温度或短线温度较近端高点（`get_indicator_trendline` 日级序列近 5 日收盘极值）回落 ≥ 20 分（峰值取昨收及之前的日级值，当帧取盘中 LLM 帧——**盘中可判定，不等收盘**） | 先手止盈**半仓**，剩余半仓按 §3.1 常规纪律 | **观察假设**：盘中帧历史数据不存在、无法精确回放；日终近似回放**不利**（s 序列触发 33 次仅 36% 次日延续下探，5 个收紧变体全部 <42%——均值回归主导下"回落"多为噪声）——阈值 20 分为初始假设，前向校准；累计 ≥8 次依成立率审定去留 |
| **C. 见顶回落预警（仅高潮链内可触达）** | 当帧节点 ∈ {高潮, 连续高潮}（云端高潮区 ≥75 稀有——本条仅高潮链可触发，高潮链的第一减仓规则）且（当帧 `temperature_level ∈ {冰点, 偏冷}`（结构化主源）**或** 当帧短线温度 < 55（佐证）任一成立） | 预判向高潮降温 / 降温转移，先手止盈**半仓** | 观察假设；累计 ≥8 次审定 |
| **D. [板块]连强终结兑现** | 持仓所属[板块]连强 run 终结：板块**翻绿**（T 日 14:30 以 `get_hot_spot_list` 实时 `avg_zdf` 判定 <0）**或**跌出市场热度前三（`get_hot_spot_list --sort_by zt_count` 前 3） | **48 小时内逢高分批兑现**（不抢跑——加速日 T+1 仍有惯性 +1.44%/100% n=8；不拖延——翻绿后 T+2 转负 -1.15% n=2） | 方向性数据（样本小）；与撤退红线 / 个股止损取更严 |

**边界**：先手减仓是**减仓动作不是清仓信号**（清仓仍走撤退红线 / 止损纪律）；与加速止盈四信号叠加时取更严（按 §0.6 分级档位执行：明确信号清仓；单一信号减半——先手减仓已半仓再遇单一信号即累计保留约 1/4 底仓，底仓至明确信号 / 撤退红线 / 个股止损再出清）；A / B / C 三条（环境 / 大盘层触发）不作用于走势健康的通道试错仓（「试错仓环境层豁免」统一条款），D（[板块]连强终结）照常作用于全部持仓；卖出理由在盯盘总结正文与摘要行操作描述中以 `node_exit` 前缀标注（注明 A/B/C/D 哪条触发，复盘从 `watch-summary-{date}.md` 汇总统计）。

**止盈松紧跟随环境（同一框架的对称面）**：

- **环境健康**（`alignment == "双强"` 且持仓方向仍在 `attack_directions`）：底仓以趋势止损（10 日线）+ §0.6 四信号管理，利润保护从"最高点回撤 -5%"放宽为**趋势破位 / 四信号触发再走**——环境 + 方向 + 个股三重强势时让趋势奔跑，不因日内小回撤兑现（心法 §4.5"非强势股少格局"的对称面：强势环境可以格局）
- **环境转弱**（命中本节任一触发）：利润保护恢复"浮盈从最高点回撤 -5%"（§3.1 原阈值），并叠加本节分批减仓——环境不支持格局时收紧兑现

### 3.1 主动评估原则与阈值表

> **定位**：本节是个股级阈值，是与 §3.0 环境级**各自独立生效的第三道防线**——环境信号管"要不要提前减"，个股信号管"形态坏了必须走"，环境级触发时个股级照常生效（§3.0 红线优先），互不替代。

**不止被动等触发，所有止盈维度每轮盯盘都必须主动评估**（评估对象为**可卖持仓** `available_volume > 0`，当日买入 T+1 不可卖的盘中跳过，见总纲 §3.3）—— 不等"破止损位 / 破 10 日线"再动作。**不及预期提前获利了结**是纪律红线，不是事后止损。**优先保住利润，非强势股少格局** —— 出现放量滞涨 / 走势与板块背离即倾向落袋，不死扛等大涨。

> **加速止盈是形态信号，只能从分时序列识别（见 §0.6），禁止用收盘快照价 / 浮亏% 代替**。

| 评估时机 | 评估维度 |
|---------|---------|
| 每轮盯盘 | ① 加速止盈信号（放量滞涨 / 长上影线 / 走势与板块背离，见 §0.6）——**不等触顶才看** |
| 每日收盘 | ② 时间止损（买入后第 3 日评估是否出现预期上涨；冲高回落不算，见 §0.6） |
| 浮盈时 | ③ 目标止盈（+10%）、④ 利润保护（从最高点回撤 -5%）、⑤ 移动止损（+50% 后回撤 -10%） |

| 类型 | 触发 | 执行 |
|------|------|------|
| 固定止损 | 买入价下跌 -5% | 立即卖出 |
| 技术止损 | 跌破买入日最低价或前低 | 立即卖出 |
| 时间止损 | 买入后 3 日内未出现预期上涨（**冲高回落不算预期上涨**：日内最高 − 收盘 ≥ 4%，口径同 §0.6 长上影——防"收盘红盘"伪正向） | 评估后离场 |
| 趋势止损 | 股价跌破 10 日线（MA10） | 立即卖出 |
| 目标止盈 | 浮盈 +10% | 减仓一半 |
| 加速止盈 | 放量滞涨 / 长上影线 / 走势与板块背离（见 §0.6） | 按 §0.6 分级执行：明确信号（时效确认 / 主力转流出 / 多信号共振）清仓；进攻方向单一信号首现减仓半仓留底仓；其余持仓任一信号成立即清仓 |
| 利润保护 | 浮盈从最高点回撤 -5%（环境健康时按 §3.0 放宽为趋势破位 / 四信号再走） | 清仓保护利润 |
| 移动止损 | 单只盈利 > +50% 后回撤 -10% | 清仓 |

> **开盘极端行情止损确认窗口**：开盘大低开 / 秒杀瞬间击穿止损位，**不机械秒割**，给约 15 分钟（9:30-9:45）确认 —— **缩量急跌快速收回 = 恐慌洗盘，不止损；放量跌破买入日最低价 / 10 日线不回头 = 趋势破位，确认止损**。触跌停、放量破 10 日线 → 立即止损不等。（固定止损在开盘极端行情下的执行细则，不废除止损纪律。）

- [ ] **环境分层减仓判定（§3.0，先于个股级止盈止损检查执行）**：`alignment` 是否 ∈ {普涨, 胶着, 逆势, 双弱}（非双强四词）？`vs_prev_analysis` 是否报告持仓所属方向走弱 / 降级？持仓板块是否进撤退名单？→ 按触发矩阵逐行核对（豁免照常核对：冰点链期间的 `channel=A/A2/B/D` 试错仓无条件不触发；**走势健康的通道试错仓**不触发环境级两行与"attack 名单消失"行——先核 `channel` 标注与试错档身份（未补足升级），再核四信号全部不成立且固定 / 技术 / 趋势 / 利润保护止损均未触发，任一走坏当轮即恢复，§3.0「试错仓环境层豁免」），命中即分批逢高减仓（首笔当轮执行，红线清仓按执行纪律第 2 条观察窗执行——刚翻红 / 加速拉升段暂缓，窗口时长分层见该条，止损立即执行）；`position_limit` 单独降低**不**触发减仓
- [ ] **止盈松紧确认（§3.0）**：环境健康（双强 + 持仓方向仍进攻）→ 底仓按趋势止损 + 四信号管理，利润保护放宽；环境转弱 → 利润保护恢复 -5% + 叠加分批减仓
- [ ] 持仓个股是否触发 §三 止损止盈？
- [ ] 持仓个股是否触发 §三 主动止盈评估？（不等触止损位，提前评估：①放量滞涨/长上影/板块背离加速止盈 ②时间止损=买入后第 3 日（**冲高回落不算预期上涨**）③浮盈时目标止盈/利润保护/移动止损）
- [ ] 每只标的买点、止损位、目标仓位是否明确？
- [ ] 是否再次确认不打板、不接力？
- [ ] **落账（买入流程硬步骤）**：买入成交后立即调 `cli.ts journal.record_decision --action buy`（direction 方向归属 / 成交价量 / 一句话理由）；否决候选后立即调 `--action veto`（含否决理由，写清关键证据）（「出手节奏与组合纪律」落账条；机械层对账补录只是兜底，不替代主动落账）

**最后输出**：
- [ ] 按 §七 完整结构输出：盯盘总结标记 → 观点总结（市场判断 / 持仓分析 / 候选分析 / 综合决策）→ 一行摘要（**不**输出"盯盘开始/盯盘结束"，轮次边界由调度日志负责）
- [ ] **输出后必做上报**：调 `cli.ts report.submit_summary watch "<当轮总结文本>"` 同步后台（每轮含"无操作"；失败即忽略，不中断）— §七「总结上报」
- [ ] **不**复述 `position_reasoning` 区间/上下沿
- [ ] **不**自创阶段 / 情绪标签（节点词逐字采用云端返回值）
- [ ] **不**自拾炸板率/大面家数/涨停破位率等指标

## 六、关键术语（账号特有规则）

> **通用术语含义（多头排列 / 放量滞涨 / 龙头 / 套利标的 / 高位 等）以心法「七、术语字典」为准**。本节只列**本账号特有**的判断细则 / 执行规则 / 优先级，不重复定义术语本身，避免双版本分歧。

| 术语 | 本账号特有规则 |
|------|---------------|
| 候选股池 | 候选股合并去重来源 = **今日趋势池（`get_strategy_trend_stocks 10`）+ 今日异动拉升池（`get_strategy_trend_stocks 4`）+ 近期异动上涨池（`get_strategy_trend_stocks 5`）+ 主力净流入榜（`get_main_inflow_top`）+ 成交额榜（`get_amount_top`）+ 小时热度榜（`get_hourly_hot_top`）**，六池全部拉取按 `stock_code` 合并去重为统一候选集（买入手册 §1.1，不存在"主池优先、其余兜底"）。异动 / 主力 / 成交额 / 热度榜来源须补验趋势形态（不降低标准）。**机器执行的池清单 / 拉取条数 / 机械剔除开关（已涨停 / 撤退方向）/ 批大小以 `memory/engine-config.json` 为单一权威源**——调整选股来源改该文件即生效（pipeline 代码不含池定义），本行为策略描述与该配置保持同步；交易所重点监管名单由引擎**必注入**（候选表"监管"列 ⚠名单内标记 + s1 注入块），是否回避由选股会话按心法 §4.1 红线自行判定（引擎不替策略决定） |

| 已撤退方向 | 板块归属为准 + 细分配套关键字判定（§0.2）；判定命中 → **红线 0%**（心法 §五 仓位红线） |
| 套利标的 | **四要素联合判定**（买入手册 §1.2）：①与龙头同方向同板块 ②资金面硬条件达标（买入手册 §0.5：累计净流入 + 换手 ≥ 5%）③当日涨幅 ≤ 7% ④分时承接 / 突破买点 |

| 低吸买点 | 时间窗口：早盘 **10:00-11:30** / 午后 **13:00-14:30（主做水下低吸）**；尾盘 14:30 后非低吸窗口（买入手册 §2.2）；昨日强势板块（Day 2+）早盘不急追（等板块企稳，买入手册 §0.8 执行节奏） |

| position_limit | 盘面分析给出的当日仓位上限百分比（0-100），**直接采用**（§0.1），不自行调档 |

## 七、输出规范

每轮盯盘输出由「盯盘总结标记」起头，后接观点总结 + 一行摘要。**注意：盯盘的"开始/结束"边界由调度日志自动打印，agent 不再重复输出"盯盘开始/盯盘结束"，只用「盯盘总结」标记自己的分析输出**：

```
========== 盯盘总结 HH:MM:SS ==========
（盯盘观点总结）
（一行摘要行）
```

- **盯盘总结标记**：观点总结的标题行，标记本轮分析输出开始
- **盯盘观点总结**：结构化分析结论（见下方板块结构）
- **一行摘要行**：`[柚子 AI] HH:MM | ...` 摘要（见下方格式）

> **标记格式固定**：`========== 盯盘总结 HH:MM:SS ==========`（等号 10 个，时间精确到秒，**逐字采用调度指令注入的「当前时间」**；未注入时先 `date "+%H:%M:%S"` 实测；禁止从 `analyze_time` / 分时 labels / 上轮记忆推算 —— 模型无时钟，自估必臆造）。**不要输出"盯盘开始/盯盘结束"** —— 轮次边界由调度日志负责，agent 重复输出会造成两份重复标记。

> **核心要求（写给人看的大白话，总纲 §八 红线的本层落点）**：观点总结回答三件事——①**当前环境怎么样**（节点 / 情绪冷暖 / 活跃方向 / 仓位额度）；②**满足 / 不满足什么条件**（今天哪些路能走、最终卡在哪一条上，只点与出手相关的关键判定）；③**操作是什么**（动作 + 一句话原因）。按板块给结论，读者要一眼看到「观点」。**禁止**：§条款编号、代码字段名与枚举值（`effective_node` / `a2_open` 这类）、数学比较式与符号链（`|30-65|=35≥15` / `∈{...}` / `✗` / `→`）直接进正文；**禁止**把 §五 checklist 的逐项检查过程（"§0.1 两指标联合 / 趋势股池+过滤 / 方向归属核验…"这类流水账检查项表格）、或全部通道逐项罗列当输出——不适用的一句"其余通道今天没资格 / 不适用"带过，只有接近触发的才展开说差在哪，判定依据译成自然语言（如"通道 D 要求尾盘前两帧大盘走稳，两帧都还是冰点，不满足"）。

### 7.1 观点总结板块结构

| 板块 | 内容（先结论，后可验证支撑） | 空值兜底 |
|------|------------------------------|----------|
| **市场判断** | 情绪（`sentiment_label`）+ alignment（`sentiment_capital_alignment`）→ §0.1 开仓资格结论；仓位上限（`position_limit`）；活跃方向；一句话市场核心特征（**禁止自拾指标数值**：炸板率 / 连板高度 / 涨跌停家数 / 量能分位等不得作为情绪论据出现——总纲 §5.1 第 2 条；LLM `market_overview` 原文内容可概述） | —— |
| **持仓个股分析** | 逐只：代码/名称、`zdf`、浮盈、§3.0 环境分层减仓状态（未触发 / 已触发第 N 笔 + 触发字段原值）、§三 止盈止损评估结论、本轮动作（持有/减仓/清仓）。**可卖持仓（`available_volume > 0`）必须带分时形态结论**（§0.6 四信号：放量滞涨/长上影/板块背离/资金背离），禁只用快照价判定；当日买入（可卖量 0）的持仓仅用持仓快照标注"今日买入 T+1 不可卖"+ `zdf` / 浮盈，不调分时接口（总纲 §3.3） | 写"当前空仓" |
| **候选个股分析** | 候选池合并去重总数 → 过滤项（已涨停/高位 `zdf`>7%/交易所重点监管禁买名单/撤退方向）→ 进入核验数；逐只取舍结论（代码/名称、`zdf`、命中买点类型或"无买点+原因"、方向归属判定结果）。盘面 `action_advice` 推荐但被纪律否决的龙头在此说明原因（如已涨停不打板、不在三池） | 写"候选池合并 N 只，过滤后无符合买点标的" |
| **综合决策** | 本轮最终动作 + 一句话核心原因（可验证事实，非主观判断） | —— |

纪律（观点总结同样受总纲 §5.6「不允许的写法」约束）：

- 情绪/仓位/活跃字段直接采用盘面返回值，**不**自创标签/调档数字，**不**复述 `position_reasoning` 区间
- 候选取舍只报客观事实（`zdf`、买点类型、方向归属判定结果），**不**写"我判断不匹配/我认为不行"等主观话术
- **不**预设未来时点动作；可写"明日需重新评估的检查项"清单（不绑定动作），禁止把 `vs_prev` 信号机械外推为下一时点具体动作
- **不**自拾炸板率/大面家数/破位率/连板高度等指标作为论据
- **买入 reason 与卖出 reason 不得混写（写法红线）**：
  - 买入 reason 只写正向买入逻辑：方向归属 + 买点类型 + 形态/量能事实（买入手册 §2.2 ①组、买入手册 §二 买点）
  - 卖出 reason 只写卖出逻辑：止损/止盈类型（§三）、加速止盈四信号（§0.6）、撤退方向（§0.2）
  - 禁止把"分时未现卖点""未触发止损""未现止盈信号""T+1 不可卖"等否决/持有侧逻辑写入买入 reason

观点总结示例（空仓、无买点场景，正文为大白话、无字段名 / 条款号 / 符号链）：

```
【市场判断】情绪偏保守但还没到撤退，不禁开仓，今天仓位上限 30%；活跃方向是存储芯片和先进封装；大盘还在系统性风险释放中（锂电崩盘拖累）
【持仓分析】当前空仓
【候选分析】三池合并 19 只去重，过滤掉已涨停 1 只、涨幅超 7% 追高风险 5 只、交易所重点监管禁买 2 只，剩 11 只逐一核验：昆仑万维、巨人网络方向不符不碰；格科微属芯片方向但该方向当日降级、买点条件不够；其余候选均冲高回落没有买点。盘面推荐的华天科技、浪潮信息都已涨停不打板，兆易创新、寒武纪不在候选池
【综合决策】空仓不操作（候选股均冲高回落无买点 + 芯片方向降级）
```

### 7.2 一行摘要行（观点总结之后输出）

格式（与总纲 §八 一致）：

```
[柚子 AI] HH:MM | 盯盘 | 节点:X | 情绪:激进/偏激进/中性/偏保守/保守 | 活跃:XX | 仓位上限:NN% | 操作:XX | 持仓:NN只
```

- 时间字段 HH:MM = 调度指令注入的「当前时间」（未注入时 `date` 实测），与盯盘总结标记同源；禁止取 `analyze_time` / 分时 labels 末值 / 自估（总纲 §八「时间取值」硬红线）
- **阶段字段** = 云端市场节点词（`market.read_market_node` 的 `effective_node`，十词：冰点 / 连续冰点 / 冰点回暖 / 升温 / 连续升温 / 高潮 / 连续高潮 / 高潮降温 / 降温 / 连续降温——节点词本身已是过程词，直接展示）；当帧节点缺位（`node_degraded=true`）时展示昨日链末节点值；读取失败时输出"该字段为空（节点读取异常）"—— 禁止自创
- 情绪字段直接采用盘面 `sentiment_label` 值，**不**自创标签
- 仓位字段直接采用盘面 `position_limit` 值，**不**自创"5成""3成"等调档数字
- 活跃字段 = `final_analysis.attack_directions[0].direction if final_analysis.attack_directions else "该字段为空"`（仅展示近期活跃方向，不复述 `reason` / `evidence`；缺位时按总纲 §5.2 字段缺位判定）
- 操作字段 = 实际动作本身（"无操作" / "买入XX N股" / "卖出XX"），**判定理由不塞进摘要行**（理由放观点总结里说），保持一行可读；"无操作"也要输出
- **不**输出 `position_reasoning` 的区间/上下沿/微调表述

### 7.5 总结上报（输出后必做）

每轮总结产出后，**必须**调 `report.submit_summary` 把当轮总结文本同步到后台（写入 `mock_log` 表），供事后回溯 agent 的判断与决策。**每轮盯盘都要上报（含"无操作"轮）**，复盘产出后上报一次。

| 阶段 | 调用 | `content` 取值 |
|------|------|----------------|
| 盯盘（每轮输出后） | `cli.ts report.submit_summary watch "<文本>"` | 当轮「盯盘总结标记」+ 观点总结 + 摘要行的完整文本（**含标记**） |
| 复盘（盘后产出后） | `cli.ts report.submit_summary review "<文本>"` | 当轮「复盘总结标记」+ 3 板块 + 摘要行的完整文本（见 §7.4） |

**content 必须与当轮终端输出逐字一致**（至少完整包含总结标记、观点总结、摘要行原文）：时间等字段随原文带出，**禁止**在上报文本中改写时间、截断内容或另拼精简格式（曾发生上报文本只拼摘要行且时间戳臆造，与实际轮次时间对不上）。

**示例**（content 含标记与换行，务必用单引号整体包裹，避免 shell 对换行/引号的转义破坏）：

```bash
# 盯盘上报
cli.ts report.submit_summary watch '========== 盯盘总结 10:45:28 ==========
【市场判断】情绪偏保守 → 不禁开仓，仓位上限 30%
【持仓分析】当前空仓
【候选分析】三池合并 19 只去重，过滤后无符合买点标的
【综合决策】空仓不操作（候选股均冲高回落无买点）
[柚子 AI] 10:45 | 盯盘 | 节点:防守 | 情绪:偏保守 | 活跃:存储芯片+先进封装 | 仓位:30% | 操作:无操作 | 持仓:0只'

# 复盘上报
cli.ts report.submit_summary review '========== 复盘总结 2026-07-09 ==========
【当日盈亏】今日 +1104.76元(+0.7%)，累计 +58.35%；持仓：格科微+4.05%、华大九天+0.5%。
【情绪演变】大盘情绪 30→44，短线温度 30→70 偏激进，主力净额 -785→+269 亿反转。
【操作反思】冰点反弹精准加仓，双笔买入合规(单只<30%/同向<50%/总仓位38.6%<盘面78%)。
[柚子 AI] 复盘 | 盈亏:+0.7% | 反思:加仓合规'
```

> - `log_type` 仅 `watch`（盯盘）/ `review`（复盘），与阶段一一对应
> - **失败隔离（硬约束）**：上报是本轮流程的**最后一步且完全旁路**。`report` 已保证上报请求 10s 超时（`_post` timeout）并吞掉**一切**异常返回错误信封（`code ≠ 200`）—— 上报在技术上不可能让本轮卡死、抛异常或中断
> - **收到任何上报结果一律忽略、不重试、不记错**：网络错 / 超时 / 服务 5xx / `code ≠ 200` 均视为"留痕失败、无所谓"，正常结束本轮；**绝不为上报重试**，**绝不因上报结果改变情绪 / 仓位 / 买卖任何决策**（上报只留痕、不参与判断）
> - 总结文本已输出给用户并写入本地 `data/`，上报失败 ≠ 本轮失败，更 ≠ 影响下次盯盘
> - `content` 为 `str` 类型注解，**不支持 `@文件` 引用**（cli 仅对 dict/list 参数展开 `@路径`）；多行文本务必用单引号整体包裹
