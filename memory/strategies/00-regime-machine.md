# 市场阶段状态机（裁决层）

> **今天处于什么阶段的唯一权威判定**。转移规则的**执行唯一权威是 journal 代码**（`read_regime_state` / `regime_advance` / `regime_rebuild`，`skills/journal/journal.py`）；本文件的转移表是**人审表述**，二者同步修订、变更记入当日 `daily-summary` 的 `strategy_changes`。二者不一致时以代码为准并立即记录修复。**agent 只读代码输出，禁止按本表手工推演状态。**
>
> 设计依据与 60 日重放数据：`memory/design/2026-09-03-multi-regime-strategy.md`（v3.1）。

## 一、判定输入与生效时序

- **输入**：收盘短线温度 `s`（唯一转移输入）、收盘大盘温度 `d`（仅落库存档与战法一双温度背书用，**不进转移条件**）
  - **日级定格值取数**：`get_daily_indicators_history` 返回 `rows` 中的"短线温度" / "大盘温度"行，格式 `标签(分数)`（如 `保守(20)`；**右括号可能全角**，如 06-29 实测 `偏保守(38）`）——解析按数字提取（`\d+` 扫描），禁止严格匹配半角括号对；提取失败 → 该日缺数
  - **盘中实时值**（仅战法一通道 A/A2/B 判定用）：当帧 `get_intraday_analysis().sentiment_analysis.sentiment_score`（短线）与 `temperature_score`（大盘）；与日级定格同源不同帧，存在帧间噪声（防噪条款见战法一分册）
- **更新时点**：无固定推进任务——盘中每轮第 0 步发现状态落后即由 `journal.regime_rebuild --write_back true --before_date <当日>` 自愈重放（只要缺就自愈，不限次数，见 §四）；**盘中永不切换阶段**（盘中读数是路径、收盘值才是定格；当日收盘定格在次日首轮盯盘自愈时进入状态）
- **生效时点**：次日交易日生效（盘中 agent 只读 `regime-state.json`）
- **唯一盘中例外**：冰点状态内的尾盘试错（战法一）是**状态内行为**，不是状态切换

## 二、状态定义与分册路由

| 状态 | 枚举值 | 含义 | 当日行为基调 | 分册 |
|------|--------|------|-------------|------|
| 防守（默认兜底） | `defense` | 无明确结构 | 禁新开仓（唯一例外：**通道 C 确认期先手**——`up_count==1` 的防守日按 `40-retreat-defense.md` §二A 轻仓先手，观察级）；持仓风控照常（不设时间窗） | `40-retreat-defense.md` |
| 冰点 | `ice_point` | 短线 ≤25 的聚簇进行中 | 晨起冰点且 **2 ≤ 簇深度 ≤ 4** 时开放试错三通道（预计算 `next_day_channel_open`）：通道 A 冰中博弈（全天，当帧短线仍 ≤25）+ 通道 A2 拉起博弈（早盘段 9:36~11:00 拉起确认 + 午后段水下低吸）+ 通道 B 尾盘认证（14:30~14:55）——条件见 `10-ice-point.md`；簇深 <2 / ≥5 无通道 | `10-ice-point.md` |
| 主升预备 | `uptrend_ready` | 连续 2 日 ≥55，第 3 日待确认 | 同防守（通道 C 确认期先手亦适用，`40-retreat-defense.md` §二A；**全量战法仍待第 3 日确认放行——轻仓先手可提前，全量入场必慢 2 日**） | `40-retreat-defense.md` |
| 主升 | `uptrend` | 预备确认通过 | 主升战法全量启用 | `20-main-uptrend.md` |
| 高位震荡 | `oscillation` | 本段曾 ≥70 后回落入 45~54（s<40 退出，回差） | 震荡战法启用（收敛、禁追、只做贯穿主线回踩） | `30-high-oscillation.md` |

**试错通道判定语义**：第 X 日通道（A / A2 / B 共用同一资格）是否开放 = 状态文件**预计算字段** `next_day_channel_open`（由代码在重放推进至第 X−1 日时写入）：当日更新后状态 = 冰点 且 **2 ≤ `cluster_depth` ≤ 4** → 开放。agent 盘中只读该字段；第 X 日当日收盘值不影响当日通道。深度 ≥5 关闭通道属长熊防御（极端处置 #1）：样本内最大簇深度 4（07-13~20 簇，其后 07-21 通道开放且为经典回升日），深度 5 是超出样本经验的保守外推。

## 三、转移表（人审表述；代码为执行唯一权威；条件按表序自上而下首个命中生效，每日至多转移一次）

| 当前状态 | 条件 | 下一状态 | 设计意图 |
|----------|------|----------|----------|
| **任意非冰点状态** | **s ≤ 25** | **冰点（簇计数，表序最优先）** | 冰点是无条件优先转移（预备态遇 s≤25 也计簇） |
| 防守 | 连续 2 日 s ≥ 55 | 主升预备 | 双日确认，过滤单日假反弹 |
| 冰点 | s > 25 且未达连续 2 日 ≥55 | 防守 | 回升未确认即退回（不允许从冰点单日跳主升） |
| 冰点 | 连续 2 日 s ≥ 55 | 主升预备 | 同上 |
| 主升预备 | 当日 s ≥ 55（连续第 3 日） | 主升（放行日） | 第 3 日仍强才放行全量战法；全量入场必慢 2 日（确认期轻仓先手见通道 C，`40-retreat-defense.md` §二A） |
| 主升预备 | 当日 s < 55 | 防守 | 确认失败 |
| 主升 | **本段内**曾 ≥70 且 45 ≤ s < 55 | 高位震荡 | 从极值回落但未崩 |
| 主升 | **本段内未曾** ≥70 且连续 2 日 45 ≤ s < 55 | 防守 | 防卡死：未见过极值的主升段，双日确认回落即结束（单日 45~54 仍保持主升，防一日游） |
| 主升 | s < 45 | 防守 | 主升结束 |
| 高位震荡 | s < 40 | 防守 | **回差设计**：边界 45 进、40 出，防边界抖动 |
| 高位震荡 | 连续 2 日 s ≥ 55 | 主升预备 | 重启确认流程 |
| 任意状态 | 长假（自然日差 ≥4，见边界定义） | 防守 | 情绪记忆断裂，全状态重置；重入按转移表重新走 |

**边界定义**：

- **"本段内曾 ≥70"**：自最近一次进入主升态起算，跨段不继承（`saw_peak_70` 离开主升即清零）
- **长假重置**：相邻交易日自然日差 **≥4** → 全量重置（journal 无交易日历的保守代理；正常周末差 3，差 4 = 中间至少 3 个连续休市自然日；误判方向仅多保守）。**长假后首个交易日盘中**：文件未损坏也不算陈旧，但按"长假盘中防御"处理（`read_regime_state` 的 `defensive_reason` 字段返回，当日按防守），盘后 `advance` 正式重置
- **缺数日规则**：当日 s 缺值 → **透明跳过**（不计入任何连续计数、不打断既有连续性，如 `55, [缺], 55` 仍算连续 2 日 ≥55），状态沿用；**连续 2 日缺数 → 强制防守**（连续计数清零、聚簇信息保留），出手动作一律暂停

**聚簇规则（伪代码口径，与代码一致）**——`days_since_ice` = 距最近冰点日的交易日数（冰点日 = 0）：

```
每个交易日收盘更新：
if s 缺值:    缺数日（透明跳过：计数与簇均不变）
elif s <= 25: # 再冰 / 延续冰点
    cluster_depth += 1; days_since_ice = 0 → 状态 = 冰点
elif cluster_depth > 0:  # 有活动簇且当日未冰（挂起）
    days_since_ice += 1
    if days_since_ice >= 3:  cluster_depth = 0; days_since_ice = null  # 簇终结
# 等价表述：冰点日起 3 个交易日内（含第 3 日）再冰 → 并入同簇（深度单调递增）；
#          第 3 个交易日收盘仍未冰 → 当日终结清零
```

## 四、状态持久化契约（`data/regime-state.json`，滚动单文件、原子覆盖写、不按日清理）

```json
{
  "updated_date": "2026-09-03",   // 最近一次盘后更新日（YYYY-MM-DD）
  "current_state": "ice_point",   // 当前状态：defense / ice_point / uptrend_ready / uptrend / oscillation
  "cluster_depth": 2,             // 冰点聚簇深度（冰点日 +1；3 个交易日内再冰并入；第 3 日收盘无冰清零）
  "days_since_ice": 0,            // 距最近冰点日的交易日数（冰点日 = 0；非冰点日逐日 +1；无活动簇为 null）
  "next_day_channel_open": true,  // 次日试错通道（A/A2/B 共用）是否开放（代码预计算：冰点 且 2≤cluster_depth≤4；agent 只读）
  "missing_count": 0,             // 连续缺数日计数（≥2 强制防守；跨日记忆须持久化）
  "up_count": 0,                  // 连续 s≥55 计数（主升预备确认用；纯 s 序列函数）
  "mid_count": 0,                 // 主升段内连续 45≤s<55 计数（未见极值段的双日回落出口用）
  "saw_peak_70": false,           // 本主升段内是否曾 s≥70（震荡出口用，跨段重置）
  "last_change_date": "2026-09-02", // 最近一次状态切换日
  "history": [                    // 轨迹（滚动 90 日，> 重放窗口 60），供复盘 / 阈值重拟合 / 战法一取昨收 s/d
    {"date": "2026-09-02", "s": 20, "d": 45, "state": "ice_point", "cluster_depth": 1}
  ]
}
```

**读写时机**：

- **读 + 自愈（状态机推进的唯一路径，不依赖复盘）**：盘中每轮第 0 步 `journal.read_regime_state --trade_date <当日>`（先于总纲 §3.1 其余 4 项）→ 阶段 + 通道资格 + 防御检测。发现 `code != 200`、`defensive_reason` 非空、或 `updated_date` 落后于最近已完成交易日（`get_daily_indicators_history` 的 `dates` 中 < 当日的最后一日）→ 当场自愈：接口返回传 `journal.regime_rebuild --write_back true --before_date <当日>` 重放写回后重读（**只要缺就自愈，不限次数**；`--before_date` 排除当日行——当日值可能是盘中临时值而非收盘定格）；自愈后仍失败 / 仍 defensive → 当日按防守处理并记录
- **写**：仅由盘中自愈的 `journal.regime_rebuild --write_back true --before_date <当日>` 原子覆盖写入；当日收盘定格在次日首轮盯盘自愈时进入状态。**复盘不再推进状态机**（复盘只做今日操作 / 不操作的旁观者分析，总纲 §7.2）
- **陈旧 / 断档 / 长假盘中防御**（自然日差代理，journal 无交易日历）：`trade_date` 与 `updated_date` 自然日差 >5 → "陈旧防御（复盘断档）"；≥4 且 ≤5 → "长假盘中防御"；**=2 → "复盘断档防御"（相邻交易日自然日差只可能是 1/3/≥4，差 2 必为中间漏了一个交易日复盘）**；三者同为当日按防守处理并记录，**复盘时一律用 `regime_rebuild` 重放补齐断档日**（不要用 advance 逐日补，会跳过中间日的温度）

**可重建性**：状态是收盘 s/d 序列的纯函数——文件缺失 / 损坏 / 陈旧时，复盘调 `get_daily_indicators_history --days 60` 取数后 `journal.regime_rebuild --raw @<file> --write_back true` 由代码完整重放重建。重放起点"防守 + 计数清零"盲初始化，偏差**有界且方向保守**（所有活跃态出口均通往防守 / 冰点，偏差最迟在首个活跃段出口自愈）。

**自校验（两级）**：① 重建验收——对 60 日序列的重放逐日符合转移表与聚簇口径（设计文档附录 A 为首个样本的对照基线）；② 常态校验——每次 `rebuild` / `advance` 后 `history` 末条与当日定格 s/d 比对，不一致即记入当日 `daily-summary` 的 `strategy_changes` 并修复。

## 六、阈值与规则变更纪律

- 阈值（25 / 45 / 55 / 70 / 聚簇间隔 / 通道深度 2~4 / 长假差 4）变更须**用户批准**，且**代码与本文档同步修订**（只改一处即判定漂移），变更记入当日 `daily-summary` 的 `strategy_changes`
- 每 60 个新增交易日滚动重拟合（L2，进化机制见设计文档 §八）；重拟合重放对比由 `regime_rebuild` 代码完成
- LLM 分析链路（prompt / 模型）重大变更会改变温度分数语义 → 记入 `strategy_changes` 并**提前触发一次阈值重拟合**
