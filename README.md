

# 柚子 AI · A 股 AI Agent 项目包

面向 Claude Code / Opencode / Codex / Workbuddy / Zcode / KimiWork 等多款 AI Agent 工具的 A 股 AI 研究项目包：行情查询、AI 盯盘、每日复盘、研究型模拟持仓记录、定时调度一体化 SDK。内置柚子 AI 完整系统指令与五层策略架构（心法纪律 / 流程总纲 / 云端市场节点裁决 / 四大战法分册 / 跨战法通用细则，`memory/` 可读可改，调教出最适合你的打法），用自然语言对话即可驱动，也可终端无人值守运行。

> **仅供学习研究，不构成任何投资建议。** 系统所有数据均来源于互联网整理，会有一定的滞后性和不准确性，据此投资造成的财产损失概不负责。所有「交易」均基于**模拟盘账号**，不涉及真实资金。⚠️⚠️⚠️⚠️⚠️

## 它能做什么

- **行情查询**：大盘汇总、热点板块、个股详情与分时、连板天梯、主力资金、主题与「今天炒什么」事件、LLM 盘面分析、自然语言选股
- **市场节点判定**：云端 AI 盘面分析节点链（冰点 / 连续冰点 / 冰点回暖 / 升温 / 连续升温 / 高潮 / 连续高潮 / 高潮降温 / 降温 / 连续降温十词）为唯一权威，盘中实时随短线情绪切换，通道资格（出手节点）由代码派生，当日该用哪套战法不再靠猜
- **AI 盯盘**：盘中自主盯盘、情绪判断、持仓止损止盈检查、按用户自建规则执行模拟交易
- **每日复盘**：盈亏与情绪复盘、操作反思、板块轮动事实记录
- **定时调度**：常驻进程按交易时段自动盯盘、盘后自动复盘，无人值守
- **状态读写**：市场节点（云端读取）、动态策略、出手台账（当日买入 / 否决记录，纯本地文件）；盯盘 / 复盘总结由调度器自动归档 Markdown 时间线
- **AI 调教**：主动指导 Agent 优化心法和交易策略，调教成最适合自己的样子

## 预置的交易体系一览（短线）

围绕情绪节点组织交易，一轮循环是"冰点 → 升温 → 高潮 → 降温 → 退潮"：**节点不对不买（退潮、高潮全禁），节点对了按窗口轻仓参与，高潮兑现、转弱减仓**（历史统计归纳，样本有限，不预示未来表现，不构成投资建议）。

**买入时点**（云端节点每轮现算，随短线情绪实时切换；当天证据核齐才出手）：

| 当帧节点 | 盘面什么样 | 什么时候买 | 买什么、注意什么 |
|---|---|---|---|
| **冰点**（昨日非冰点链） | 首冰当日 | 不买 | 首冰当日不操作，只记录观察——节点收盘才定格进日级链，当天仍按前一节点规矩管 |
| **冰点 / 连续冰点**（昨日 = 冰点） | 潜在双冰日 | 10:00 以后或尾盘 14:30~14:55 | 小仓试错：回暖共振了就买当天资金一起进攻的方向；还在冰就尾盘低吸已回调主线（近 10 天 ≥3 次进前三、当天跌出涨停前三——冰点里逆势坚挺的可能补跌，不碰；别抄底） |
| **冰点 / 连续冰点**（昨日 = 连续冰点） | 深冰延续 | 全天 | 小仓试错；当帧有共振方向就买共振方向（可放宽一点仓位）；还冰就只买已回调的主线板块（逆势坚挺的不碰）；没有符合条件的就不出手 |
| **冰点回暖**（脱冰首日） | 修复迹象出现 | 盘中 10:00~14:00 或尾盘 14:30~14:55（两条窗口共享当天一笔额度） | 小仓修复先手（单只 5%~10%）；收盘修复没确认（次日节点回落），次日无条件离场 |
| **升温**（上行首日 · 待确认态） | 转暖初段 | 早盘 10:00~11:00 或尾盘 14:30~14:55 | 轻仓先手（试错档）；午后只做低吸 |
| **连续升温**（确认态） | 趋势持续 | 同上升温窗口 | 主出手窗口：可补足升级；强势板块参与，午后只做低吸 |
| **高潮 / 连续高潮** | 涨到高潮区（≥75） | 不买 | **只兑现不加仓**——禁一切新开仓（含补足），只持仓、只减仓，随时兑现 |
| **高潮降温**（高潮回落没崩） | 主线还在 | 不做先手 | 只做反复活跃主线的回踩确认买点；禁追涨、不开先手通道 |
| **降温 / 连续降温** | 情绪走弱 | 不买 | **没有例外——节点不对，题材再强都不买**（连降越久越严） |

市场节点一票否决：节点不对，题材再强都不买。节点对了，买入只管三件事：

- **时间点**：按上表窗口执行；板块级机会——某板块连续 2 天市场最热（涨停数居前三）时，升温链、冰点链、冰点回暖节点的尾盘 14:30~14:55 可参与（不追涨停，当天错过不追认）
- **买入对象**：板块内趋势股（站上 5 日线且趋势向上），形态含回踩低吸、分时承接、突破（细则见策略）
- **仓位**：轻仓为主；单只 ≤30%、同板块合计 ≤50%、总量不超过账户仓位上限

**加仓**：首笔试错仓不超过目标仓位的一半，**当日不加仓**；次日起验证成立（板块不退榜、温度不回落，且当日节点许可）才分笔补足；仓位峰值止步于升温链，高潮链与降温链不加仓。

**卖出**：节点转弱当天逢高减仓；持仓板块翻绿或跌出市场前列，48 小时内分批兑现；个股止损止盈照常执行，从不过夜拖。

**禁开仓**：降温 / 连续降温节点、高潮链（只兑现）、当日情绪保守且资金双弱（冰点链先手通道 A/A2/B/D 豁免——冰点期此属常态而非恶化）、交易所监管名单等情形下，禁止一切新开仓。

每条规则标注数据依据（历史回放 / 观察级待验证），出手记录标记通道来源，按实际表现定期审定去留。细则见 [`memory/strategies/`](./memory/strategies/) 与 [`memory/dynamic-strategy.md`](./memory/dynamic-strategy.md)。

## 快速开始

### 环境要求（下载包用户必读）

| 项 | 要求 | 说明 / 自检方式 |
|---|---|---|
| **Node.js** | **≥ 22.18**（建议装 22 LTS 最新版） | 项目是 TypeScript 源码，**由 Node 直接执行**（22.18 起默认开启类型擦除），无需任何编译；`node -v` 自检 |
| **npm** | 随 Node 一起安装即可（≥ 9） | 只用于 `npm install` 装依赖；`npm -v` 自检 |
| **依赖安装** | `npm install` 必做一次 | 下载包**不含 node_modules**（体积大且含平台相关内容），首次使用需装一次：pi agent 引擎 + adm-zip |
| **模型凭证** | 二选一 | ①交互登录（推荐）：`npx pi-coding-agent /login`（凭证存 `~/.pi/`，全局生效、不入仓库），把 `.env` 预置的 `PI_MODEL` 行注释掉即可；②API key（服务器 / CI）：下载包 `.env` 已预置推荐模型，只需在 `MINIMAX_CN_API_KEY=` 后面填上 key |
| **模型选择** | 已预置 | 下载包 `.env` 已预置 `PI_MODEL=minimax-cn/MiniMax-M3.1-Flash`（MiniMax 国内站）；换模型改这一行的 provider/模型 两段，并把 key 填到对应行（**provider 必须与密钥站点配套**，如 `minimax-cn` = 国内站 `MINIMAX_CN_API_KEY`，配错会 401；可选组合与配套写法见 `.env.example`，留空的 key 行会被引擎忽略） |
| **模拟盘密钥** | `STOCK_SECRET_KEY` | 下载包的 `.env` 已自动写入专属密钥；手动复制代码时按 `.env.example` 填 |
| **Python** | **不需要** | 全项目已 TypeScript 化，无解释器 / pip / `__pycache__` 依赖 |
| **构建工具** | **不需要** | 没有编译步骤，也不产出任何 bundle 目录；`npm run check` 只是可选的类型检查 |

```bash
node -v                          # 需 >= v22.18.0（低于此版本无法直接运行 .ts）
npm install                      # 安装 pi 引擎等依赖（一次即可）
npx pi-coding-agent /login       # 首次使用：登录模型供应商；或跳过登录，直接在 .env 的 MINIMAX_CN_API_KEY= 后填 key
node src/scheduler.ts            # 启动无人值守盯盘
```

> 只想在 IDE 里对话、不跑后台进程（方式 A）？同样需要 Node ≥ 22.18——第三方 agent 会通过 `node skills/*/cli.ts` 调用接口，但**不需要** pi 引擎与模型凭证（IDE 自带自己的模型），只需 `.env` 里的 `STOCK_SECRET_KEY`。

**常见问题**

| 现象 | 原因与处理 |
|---|---|
| 报 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` / 无法加载 `.ts` 文件 | Node 版本低于 22.18，升级到 22.18+（22 LTS 最新版即可） |
| `npm install` 网络超时 / 失败 | 配置 npm 镜像或代理后重试；服务器上可先在别处装好再拷 `node_modules` |
| `npx pi-coding-agent /login` 无法交互（服务器 / CI） | 改用 API key 方式：在 `.env` 填 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `MINIMAX_API_KEY` / `KIMI_API_KEY` 等（见 `.env.example`），无需登录流程 |
| 报 `401 invalid api key` | 密钥与 provider 站点不配套（国际站密钥配 `minimax`、国内站密钥配 `minimax-cn`）；用 `PI_MODEL=provider/model` 显式指定，或检查该站对应的 `*_API_KEY` 变量名 |
| 盯盘轮报「No API key found」 | 凭证未配置：交互登录或填 `.env` 的 `*_API_KEY` |
| 想固定用某个模型 | 在 `.env` 设 `PI_MODEL`（如 `minimax-cn/MiniMax-M3.1-Flash`、`anthropic/claude-sonnet-4-5`）与可选的 `PI_PROVIDER` |

## 一次盯盘时序（流水线）

v2 把一轮盯盘严格拆成「代码干的活」和「LLM 干的活」：**代码尽可能提前拉取数据、整理数据、注入内容；LLM 只做判断分析、给出操作建议和具体数值；代码再拿这些结果钳制、流转、执行、留痕**。策略阈值永远写在 `memory/` 手册里由会话读取，代码零持有——文档改不动工程安全不变量，代码也不会越界做交易判断。

调度器（`node src/scheduler.ts`，交易时段每 5 分钟一轮）触发后，一轮盯盘按以下时序执行：

**第 0 步 · 机械层前置（`src/watch-context.ts`，零 token）**——代码在会话开始前完成全部拉取与算术，拼成注入块：云端市场节点读取（当帧实时节点 + 日级链组合派生通道资格）→ 五项必读（盘面分析 / 交易所监管名单 / 账户 / 持仓 / 温度历史）→ 纪律预算（出手台账对账补录、今日买入不可卖暴露、板块热度前 3、当日委托清单）→ 持仓复核预拉（每只可卖持仓的分时 / 板块归属 / 买入溯源）。

**第 1~6 步 · 会话流水线（`src/runtime/pipeline/`）**：

| 阶段 | 谁做 | 干什么 |
|---|---|---|
| s1 判定 | LLM | 消费注入块 + 策略手册，产出开仓资格 / 情绪 / 仓位上限 / 进攻与撤退方向 |
| s2 卖链 | LLM | 逐只可卖持仓核分时三件套，产出卖出决策（会话失败时由代码兜底执行止损） |
| s3 候选池 | 纯代码 | 六池拉取合并去重 → 监管名单标记 → 已涨停 / 撤退方向剔除 → 蛇形分批，零 LLM |
| s3a 批初选 | LLM | 每批候选 ≤3 只，宁缺勿滥 |
| s3b 终选 | LLM | 出线者同台终选，产出买入预算与权重分配 |
| s4 核验 | LLM | 终选股过心法红线 / 资金面硬条件 / 买点规则，逐只给出 pass / reject |
| s5 终裁执行 | LLM + 代码 | LLM 从心法**逐字读出**仓位红线数值，代码做五重钳制算术（可用资金 / 仓位上限 / 单只 / 同方向 / 单笔降档封顶）后才下单；红线缺失即 fail-closed 全不下单 |
| s6 总结 | LLM | 全轮事实 digest → 盯盘总结 + 摘要行（会话失败时机械骨架兜底，保证总有产出） |

**安全网贯穿全程**：仓位红线缺失或非法即全轮不下单（安全默认，文档改不动）；轮级墙钟 300 秒（预留 60 秒给总结产出）+ 各会话独立预算闸（超限强制收尾产出）；任一环节失败降级记录、整轮不断链。每股从候选池到成交 / 落选的完整判决路径留痕在 `data/watch_scheduler_logs/sessions-*.jsonl`，「为什么没买 X」一次可查。

**盘后复盘（每晚 21:00）与盯盘对称**：r0 事实装配（纯代码：账户 / 委托 / 温度历史 / 板块热点 + 全天盯盘总结全文预喂）→ r1 复盘会话（当日盈亏 / 情绪演变 / 操作反思）→ 失败时骨架兜底。复盘不做推演、不选股、零节点职责（节点判定唯一权威在云端），也不自动改写策略手册。

验证与排障：`npm run check`（类型检查）、`node src/runtime/pipeline/main.ts --check`（零 LLM 自检）、`--dry`（全链干跑）；排障入口 `data/watch_scheduler_logs/`（逐轮会话收发留痕）与 `data/pipeline-trace-*.jsonl`（各阶段流水）。

- **系统总纲（流程控制）**：[`AGENTS.md`](./AGENTS.md)（Opencode / Codex / Workbuddy / zCode / KimiWork 等第三方 Agent 工具）——总流程控制、必调接口、字段含义与输出规范
- **心法（认知与纪律）**：[`memory/trading-mindset.md`](./memory/trading-mindset.md)——永远要做 / 永远不做的红线 + 业内术语字典，每个用户最核心的纪律要求（按需修改）
- **裁决层（云端市场节点）**：[`memory/strategies/00-market-node.md`](./memory/strategies/00-market-node.md) + `skills/mock` 的 `market.read_market_node`——「今天处于什么节点」的唯一权威判定在云端 AI 盘面分析，本地只读消费、零判定零重放
- **战法层（各阶段细则）**：[`memory/strategies/`](./memory/strategies/) 四大战法分册——冰点博弈 `10-ice-point.md` / 高潮链持仓管理 `20-main-uptrend.md` / 高潮降温切换 `30-high-oscillation.md` / 降温防守与升温出手 `40-retreat-defense.md`
- **通用层（跨战法细则）**：[`memory/dynamic-strategy.md`](./memory/dynamic-strategy.md)——市场节点索引、选股六池、止损与 T+1、复盘流程与经验教训
- **接口索引**：[`skills/mock/SKILL.md`](./skills/mock/SKILL.md)、[`skills/journal/SKILL.md`](./skills/journal/SKILL.md)（函数签名以各 `.ts` docstring 为准）
- **自更新工具**：`node src/tool.ts update [skills|memory|agents|all]`（走 v2 专用升级接口 `/api/web/skills/download_v2`，覆盖前自动备份；`check` 查更新、`status` 看版本。v1 的 `python tool.py` 更新通道已关闭，见顶部版本说明）
